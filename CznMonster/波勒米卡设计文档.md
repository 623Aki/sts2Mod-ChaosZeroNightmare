### 1.3 勘误：`.srcs` 不是骨架

`_filelist.txt:14` 写「`.srcs` Spine 骨架文件（.skel 二进制）」，但实测：

- `model_data/1001013.srcs` 的字节头是 `7B 0D 0A ...`，即**文本 JSON**；
- 内容是 `command_sets`：把 `m_attack_01_1` / `buff_1_1` 等**动作指令**映射到
  `normal_skill4` / `normal_skill2_3` 等**骨架动画名**；
- 真正的骨架是 `model/<ID>.json`（Spine 3.8.79 工程，含 animations）。

**结论**：转 4.2.11 要对 `model/<ID>.json` 做转换，不能把 `.srcs` 改名成 `.skel`。

转换命令（与 `tools/gen_skel_tres.ps1` 配套）：

```powershell
$c = 'G:\sts2Mod\tools\SpineSkeletonDataConverter.exe'
& $c 'G:\CZN原始素材提取\model\1001013.json' `
     'G:\sts2Mod\CznMonster\CznMonster\animations\monsters\polemica\polemica.skel' -v 4.2.11
Copy-Item 'G:\CZN原始素材提取\model\1001013.atlas' '...\polemica.atlas' -Force
Copy-Item 'G:\CZN原始素材提取\model\1001013.png'   '...\polemica.png'   -Force
& 'G:\sts2Mod\tools\gen_skel_tres.ps1' -ProjectDir 'G:\sts2Mod\CznMonster' `
     -ResourceDir 'G:\sts2Mod\CznMonster\CznMonster\animations\monsters\polemica'
```

## 2. 原始机制解构

### 2.1 七阶段状态机（原文）

来源：`db/monster(invader)@monster_pattern_set.json` 与
`行动轨迹与切换条件.txt`。每个阶段绑定一个 `pattern`（行动卡池）。

| 阶段 | pattern | 条件 0 | 条件 1 | 条件 2 | 进入动作 |
|---|---|---|---|---|---|
| P1 | `pt1` | `0338≥1 且 存活怪==1` → P3 | `0339==3` → P2 | `HP%<50` → P4 | `pt1_01`（召集 + 强化） |
| P2 | `pt2` | 1 回合计时器 → P1 | `HP%<50` → P4 | — | `pt2_00`（重置计数） |
| P3 | `pt3` | `0339==3` → P2 | `存活怪≥2` → P1 | `HP%<50` → P4 | `pt3_00`（重置 0337） |
| P4 | `pt4` | 1 回合计时器 → P5 | — | — | `pt4_00`（处决小怪 + 护盾） |
| P5 | `pt5` | `存活怪==1` → P7 | `0339==3` → P6 | — | `pt5_01`（被动：召集精英） |
| P6 | `pt6` | 1 回合计时器 → P5 | — | — | `pt6_00`（重置计数） |
| P7 | `pt7` | `0339==3` → P6 | `存活怪≥2` → P5 | — | 无专属卡；卡池指向 `pt3_10` |

> 条件按 0→1→2 的顺序判定，**顺序有意义**（例如 P5 先判「无小怪→P7」，再判「0339==3→P6」）。

### 2.2 阶段可达性分析（重要发现）

把状态效果与卡牌可用条件对齐后，按**可见 DB** 推断原数据里的 P2 / P6 **不可达**：
（不排除游戏内还有 `cs` 自身的隐藏规则，例如 `cs02_0340` 在召唤物行动时反哺 `0339`；
但提取出的 `condition` / `skill_eff` 里没有这条链路。）

1. `0339`（换防计数）在可见 DB 里**只有** `pt1_01` 会 +1；
2. `pt1_01` 的可用条件是 `cd_icre_ics_mon_0695_eq00`，即 **`0338 == 0`**；
3. `pt1_01` 自身会 `0338 +2`，而 `0338` 只有 `pt4_10`（P4 护盾）会清零；
4. P1 再次进入时 `0338` 仍是 2，`pt1_01` 不可用 → `0339` 无法再增加；
5. 因此 `0339` 最多到 1，`0339==3` 永远不成立 → **P2、P6 是死内容**；
6. P7 没有任何召唤卡，一旦进入 P7 就不可能满足「存活怪≥2→P5」，所以 **P7 是最终攻击循环**。

**原数据实际可玩到的流程**：

```
P1（召唤一波 + 攻击） → 小怪死光 → P3（单体攻击）
   → HP<50% → P4（处决小怪 + 护盾，1 回合） → P5（召唤精英 + 攻击）
   → 精英死光 → P7（终局攻击循环直到死亡）
```

**本设计的处理**：保留「3 拍换防」的设计意图，用一个可达的「孵化仪式」计数器替代
`0339`，让 P2 / P6 作为**换防动作**在每个循环的第 3 拍触发（详见 §4.4/§4.5，
待确认项见 §11 Q5）。这是本文对原数据最大的一处**有意偏离**。

## 3. 数值换算规则（CZN → STS2）

### 3.1 伤害：`STS = round(CZN% × 0.15)`

以「Boss 主攻击 200% ≈ 第 3 章首领的一次重击 30」为锚点，得攻击力基准 15。
所有召唤物 `stat_atk_pct = 100`，共用同一基准。

| CZN 百分比 | 200% | 160% | 150% | 100% | 60% | 40% |
|---|---|---|---|---|---|---|
| STS2 换算 | 30 | 24 | 22 | 15 | 9 | 6 |
| 实装（平衡后） | 30 | 24 | **18** | **12** | 9 | 6 |

> **平衡调整（§11 Q13）**：按换算值直落 15/22 时，第一波（兵蚁×2 + 盾蚁）同回合
> 总输出 33 > Boss 单发 22，且兵蚁 Rally 给全队 +1 力量无上限约束，滚雪球过强。
> 实装将 100% 档 15 → 12（升华 13）、150% 档 22 → 18（升华 20）：
> 第一波总输出 24 + 4~12，落在 Boss 一次冲锋 / 突刺的上下；150% 精英攻击档同比例下调。

升华「致命敌人」：全表 +2 / +2 / +2 / +1 / +1 / +1（与原生命中约 +7% 一致）；
平衡调整后的 18 / 12 档沿用 +2 / +1 的绝对增量。

### 3.2 生命：以「精英 68% = 100 HP」为锚点

5 只召唤物共享同一基准，取精英中值 68% 对应 100 HP，得 `1% ≈ 1.47 HP`：

| 对象 | CZN HP% | 公式 | 设计值（min–max） |
|---|---|---|---|
| 波勒米卡 | 302–315 | ×1.47 | **444–463 → 450（升华 475）** |
| 军团兵蚁 `1001009` | 25–27 | ×1.47 | 37–40 → **38（升华 40）** |
| 军团盾蚁 `1001010` | 28–30 | ×1.47 | 41–44 → **42（升华 44）** |
| 岩壳虫 `1001019` | 65–72 | ×1.47 | 96–106 → **102（升华 108）** |
| 翼壳虫 `1001018` | 65–72 | ×1.47 | 96–106 → **96（升华 101）** |
| 壳虫 `1001004` | 65–72 | ×1.47 | 96–106 → **105（升华 111）** |

> 450 落在原生第 3 章首领（女王 400/419、知识恶魔 379/399、实验体 300–313）之上，
> 与 RANK_S 的「超级首领」定位一致，但不至于变成 700+ 的血牛。
> 若坚持按原比例 1:1 换算，Boss 会到约 790 HP，不建议（§11 Q8）。

### 3.6 章节缩放（随机模式必须）

上游文档 §6.2 的随机模式允许 CZN 首领出现在第 1–3 章。同一套 450 HP 放在第 1 章会过强，
因此按章节乘系数（先取升华值，再乘章节系数，向下取整）：

| 章节 | HP | 伤害 | 格挡 |
|---|---|---|---|
| 第 1 章（index 0） | ×2/3 | ×3/4 | ×3/4 |
| 第 2 章（index 1） | ×5/6 | ×9/10 | ×9/10 |
| 第 3 章（index 2） | ×1 | ×1 | ×1 |

结果示例（Boss）：`300 / 375 / 450` HP，`22 / 27 / 30` 主攻击，`18 / 21 / 24` 重击，
`33 / 40 / 45` 格挡。
召唤物同理：兵蚁 `25 / 31 / 38`，岩壳虫 `68 / 85 / 102`。

> 实现用 `PolemicaScaling.ActIndex` 静态值（由首领替换补丁在选中该 Boss 时写入
> `act.Index`），`MinInitialHp` / 伤害 getter 都读它。控制台单测时默认 2。

### 3.7 多人

- 生命：走原生 `Creature.ScaleMonsterHpForMultiplayer`（`CombatState.cs:242`），
  自定义值语义为「单人血量」。
- **伤害/格挡/层数不缩放**（原生也只缩放 HP）。
- 召唤数量固定 3（不随玩家数增加）；否则 4 人局会有 12 只小怪。
- 计数：Boss 的仪式阈值固定 3，不随玩家数变化。

| `add3` | `(1280, 740)` | 右前，离 Boss 最近（兵蚁） |
| `boss` | `(1650, 695)` | Boss 站位（最右、略靠后） |

- **间距是手算的，引擎不会替你排**：带槽位的遭遇走
  `NCombatRoom.PositionCreaturesWithSlots()`（`NCombatRoom.cs:315`，召唤物走 `:546`），
  只是把节点吸到 Marker 的全局坐标，没有 `PositionEnemies()` 那套按包围盒累加的算法。
  取值规则：`中心距 ≥ 半宽A + 半宽B + 30~40`（原版同尺寸小怪的习惯间隙）。
  当前小怪半宽 92 / 118 / 85，Boss 半宽 258.5 → 实际间隙 40 / 40 / 20。
- **Boss 视觉 0.95 → 0.85**：`polemica.tscn` 的 `Visuals.scale` 改小后，
  `Bounds`（578×556 → 517×497.5）与 `CenterPos` / `IntentPos` / `TalkPos` 必须同比例 ×0.895，
  否则点击框、意图、处决特效能点会和画面错位。
- **屏幕换算**：`屏幕x = 960 + (markerX − 960) × 0.82`（`CombatSceneContainer` 的 pivot 是 960,540）。
  Boss 包围盒右边界别超过 ~1900，超过会在开场 `_Ready`
  触发 `AdjustCreatureScaleForAspectRatio()` 把整个敌人容器缩一次并左移；
  而且它只在开场和窗口尺寸变化时跑，**召唤时不会重排**。
- 三个槽位的 y 差 34px 是刻意错位（原版 `exoskeletons_normal` 也是 705/737/724），
  但**别靠 y 做前后遮挡**：敌人节点没有按 y 排序的 z，绘制顺序 = 加入顺序。
- `FullyCenterPlayers = false` + `GetCameraScaling() => 0.82f` + `GetCameraOffset() => Vector2.Down * 35f`
  （以实际包围盒在实机里微调）。

### 4.5 分支条件（伪代码）

```csharp
// P1：先判「小怪清空」，再判「仪式满」，最后判「半血」
p1.AddState(soloStrike, () => SummonedOnce && LivingAdds == 0);
p1.AddState(rebrood,    () => BroodAmount >= 3);
p1.AddState(shell,      () => HpPercent < 0.5);
p1.AddState(legionCharge, () => true);

// P3：先判「仪式满」，再判「小怪≥2」，最后判「半血」
p3.AddState(rebrood,  () => BroodAmount >= 3);
p3.AddState(broodCall,() => LivingAdds >= 2);
p3.AddState(shell,    () => HpPercent < 0.5);
p3.AddState(soloStrike, () => true);

// P5：先判「无小怪」，再判「仪式满」
p5.AddState(finalStrike,  () => LivingAdds == 0);
p5.AddState(eliteRebrood, () => BroodAmount >= 3);
p5.AddState(secondWind,   () => true);

// P7：先判「仪式满」，再判「小怪≥2」
p7.AddState(eliteRebrood, () => BroodAmount >= 3);
p7.AddState(secondWind,   () => LivingAdds >= 2);
p7.AddState(finalStrike,  () => true);
```

`LivingAdds` = `CombatState.GetTeammatesOf(Creature).Count(c => c != Creature && c.IsAlive)`；
`HpPercent` = `Creature.GetHpPercentRemaining()`。

### 4.6 仪式计数与「3 拍换防」

- 定义：Boss 身上挂 `PolemicaBroodPower`，`Amount` 0–3；**除换防/护盾外的每次行动结束 +1**。
- 满 3 后，**下一次**分支进入 `REBROOD` / `ELITE_REBROOD`（不是当拍立即换）。
- 换防与护盾把计数清零（移除 Power）。
- 设计效果：Boss 每 3 次行动换一波召唤物，形成稳定的「召集 → 进攻 → 换防」节奏；
  玩家可以通过「在换防前清光小怪」阻止 Boss 获得换防力量，从而赚取节奏。

> 原数据里 `0339` 只在 `pt1_01` +1 且该卡只能放一次，导致 P2/P6 永远不可达（§2.2）。
> 本设计把「仪式」提升为**可见、可达的 3 拍循环**，是对原意的补全而不是改写玩法方向。

> `MonsterModel.VisualsPath` 是 `protected virtual`（`MonsterModel.cs:75`），
> 可以 override 到 `res://CznMonster/...`；
> 但 `EncounterModel.ScenePath` 是私有写死（`EncounterModel.cs:181`），
> 遭遇场景必须放在 `res://scenes/encounters/polemica_boss.tscn`。
> 能力图标与参考 mod 一样挂 `res://images/...`（`PowerModel.cs:104-108`），
> **不能**写成 `res://CznMonster/images/...`。

### 5.2 视觉场景契约

每个 `creature_visuals/*.tscn` 必须包含：

| 节点 | 类型 | 要求 |
|---|---|---|
| `Visuals` | `SpineSprite` | `unique_name_in_owner = true`，`skeleton_data_res` 指向 `_skel_data.tres` |
| `Bounds` | `Control` | `unique_name_in_owner = true`，覆盖包围盒 |
| `CenterPos` | `Marker2D` | `unique_name_in_owner = true` |
| `IntentPos` | `Marker2D` | `unique_name_in_owner = true` |
| `TalkPos` | `Marker2D` | `unique_name_in_owner = true` |

缩放标定：

- 不要直接使用 `.setting` 的 `scale: 1.3`（那是 CZN 的渲染标定）。
- 先用 `SpineSkeletonDataConverter.exe` 把 `.skel` 导回 JSON，量 `normal_idle` 的
  骨骼包围盒高度；`scale = 目标高度 / 包围盒高度`。
- Boss 目标高度约 **520–600 px**（原生女王 `Bounds` 高约 655 px、SpineSprite scale 0.14，
  但女王的骨架单位与 CZN 不同，必须实测）；召唤物目标 180–220 px。
- 用 `CZN_AnimLab` 加载 tscn → 勾选动画 → 微调 scale / position，确认
  `Bounds`、`CenterPos`、`IntentPos` 与血条不重叠。

### 5.3 Animator 映射（必须 override）

CZN 的待机动画叫 `normal_idle`，不是 `idle_loop`。若沿用默认 `GenerateAnimator`，
日志会刷 `could not find 'idle_loop'` 且角色不动（上游手册 §3.4 同源问题）。

**勘误（2026-10-20）：引擎不会发 `"Spawn"` 触发器。** `AnimState` 只认
`Hit` / `Dead` / `Attack` / `Cast` / `PowerUp` 等引擎内置触发器，
登场动画必须做成 `CreatureAnimator` 的**初始状态**（原生 Parafright / GasBomb 同做法，
见 `Parafright.cs` / `GasBomb.cs`）。原先设计里的 `Spawn → normal_enter` 一行作废。

各怪的实际映射（`GenerateAnimator` 实现，括号内为 `TriggerAnim` 的等待秒数）：

| 怪物 | 初始状态 | `Hit`（眩晕时） | `Hit` | `Dead` | 其它触发器 |
|---|---|---|---|---|---|
| 波勒米卡 1001013 | `normal_enter` | `normal_groggy` | `normal_hit` | `normal_death` | `AttackHeavy`→`normal_skill1_3`(1.70)、`AttackFast`→`normal_skill4`(1.03)、`Summon`→`normal_skill2_3`(2.43)、`Shell`→`normal_skill3`(2.60)、`Fatal`→`normal_fatal`(1.5) |
| 军团兵蚁 1001009 | `normal_summon` | `normal_groggy` | `normal_hit` | `normal_death` | `RallyAttack`→`normal_skill1`(1.13)、`HarassAttack`→`normal_skill2`(1.03)、`Surprise`→`normal_surprise`(0.55) |
| 军团盾蚁 1001010 | `normal_summon` | `normal_groggy` | `normal_hit` | `normal_death` | `Attack`→`normal_skill1`(1.13)、`Cover`→`normal_skill2`(1.03)、`Surprise`→`normal_surprise`(0.55) |
| 岩壳虫 1001019 | `normal_enter` | `normal_groggy` | `normal_hit` | `normal_death` | `Crush`/`Guard`→`normal_skill1`(1.50)、`Harden`→`normal_skill2`(0.90)、`Fatal`→`normal_fatal`(1.5) |
| 翼壳虫 1001018 | `normal_enter` | `normal_groggy` | `normal_hit` | `normal_death` | `Attack`/`Guard`→`normal_skill1`/`normal_skill2`(1.50)、`Fatal`→`normal_fatal`(1.5) |
| 壳虫 1001004 | `normal_enter` | `normal_groggy` | `normal_hit` | `normal_death` | `Attack`/`Guard`→`normal_skill1`/`normal_skill2`(1.50)、`Fatal`→`normal_fatal`(1.5) |

四条通用规则：

- 非循环动画统一 `NextState = idle`；`normal_death` 不设 NextState。
- **眩晕**：引擎没有 stun 触发器，用 `AnimState` 的条件分支实现 ——
  先 `AddAnyState("Hit", normal_groggy, () => Creature.IsStunned)`，
  再 `AddAnyState("Hit", normal_hit)`。`AnimState` 按**插入顺序**取第一个条件成立的分支，
  所以带条件的那条必须先加（`Creature.IsStunned` == `Monster.NextMove.Id == "STUNNED"`）。
- **初始化**：`CreatureAnimator(initialState, controller)` 构造时就会 `SetNextState`，
  所以登场动画会在进房时真正播一遍。
- **一只怪有多套攻击动画时不要共用 `Attack` 触发器**：兵蚁的「战吼突刺」用
  `RallyAttack → normal_skill1`，「撕咬」用 `HarassAttack → normal_skill2`；
  盾蚁用 `Attack`/`Cover`；精英用 `Crush`/`Guard`/`Harden`。
  岩壳虫的 `Crush` 与 `Guard` 两种攻击都落在 `normal_skill1`（素材里也只有这一段
  攻击动画），不额外拆分触发器。

音效**不**依赖 `TriggerAnim`：它只对 `Attack` / `Cast` / `PowerUp` 自动找音效，
自定义触发器一律靠显式 `CznMonsterSfx.Play(...)` 或 `WithAttackerFx(...)`（见 §5.4）。

### 5.4 音效

**结论：不再用原生事件占位，改用「占位路径 + 前缀补丁 + 本地 ogg」。**
28 条 CZN 采样已用 `tools/extract_fmod_bank.py` 导出到
`res://CznMonster/audio/sfx/polemica/<怪物 id>/*.ogg`，全部进 pck。

为什么不能直接把 `se_*` 填进 `AttackSfx` / `DeathSfx`：那些属性只能是
`event:/sfx/...` 事件路径，`se_*` 只是 bank 内的采样名，填进去必然 404。
所以走这条链路：

| 环节 | 实现 |
|---|---|
| 占位路径 | `AttackSfx` / `DeathSfx` / `HurtSfx` 返回 `event:/sfx/enemy/enemy_attacks/cznmonster/<ENTRY>/<clip>`（`CznMonsterSfx.Placeholder`） |
| 拦截 | `Registration/CznMonsterSfxPatch.cs`：`SfxCmd.Play(string,float)` 前缀补丁，命中前缀就播本地 ogg 并返回 `false` 吞掉原调用 |
| 死亡单独拦 | `SfxCmd.PlayDeath(MonsterModel)` **不经过** `Play`，直接调 `NAudioManager.PlayOneShot`，必须再打一条补丁 |
| 零侵入 | 补丁只识别本前缀，其余路径原样 `return true` 走原实现（铁律 6），先判 `instance is <本角色>` |
| 播放器 | `CznMonsterSfx` 内部维护最多 4 个 `AudioStreamPlayer`，挂在 `NCombatRoom.Ui` 下（离房即随房间释放），总线 `SFX`，采样按需 `ResourceLoader.Load` 并按路径缓存 |
| 预热 | 订阅 `CombatManager.CombatSetUp`，**只有本场遭遇是 CZN 首领**时一次性读入 28 条，避免每次进战斗白读 |

怪物 entry → clip 映射（clip 名对齐动画 / 动作语义）：

| 怪物 | clip → 采样文件 | 触发点 |
|---|---|---|
| POLEMICA 1001013 | `enter`→`se_corpsleader_formica_normal_enter`；`skill1_3`→`..._normal_skill1_3`；`skill2_3`→`..._normal_skill2_3`；`skill3`→`..._normal_skill3`；`skill4`→`..._normal_skill4`；`fatal`→`se_1001013_normal_fatal`；`death`→`se_1001013_normal_death`；`hurt`→`se_1001013_groan_1/2/3`（**随机一条**） | 登场 `AfterAddedToRoom`；技能用 `WithAttackerFx` / 显式 `Play`；`hurt` 走 `HurtSfx`；`death` 走 `PlayDeath` 补丁 |
| LEGION_SOLDIER 1001009 | `enter`/`summon`→`se_coorte_normal_enter`；`skill1`→`..._skill1`；`skill2`→`..._skill2` | 登场用 `summon`；两个攻击触发器 |
| LEGION_SHIELD 1001010 | `enter`/`summon`→`se_armored_coorte_normal_enter`；`skill1`；`skill2` | 同上 |
| ROCK/WING/SHELL 1001019/1001018/1001004 | `enter`；`skill1`；`skill2`；`fatal`→`se_<id>_normal_fatal` | 登场 + 两个攻击触发器（岩壳虫的 `Harden` 用 `skill2`） |

四条采样缺失时的约定（重要，避免「静音 = bug」的误判）：

- **兵蚁 / 盾蚁没有 `summon` 采样**，登场复用其 `enter` 采样（动画仍用 `normal_summon`）。
- **兵蚁 / 盾蚁没有 `fatal` 采样**，被处决时不额外发声（`ExecuteSfxClip => null`），
  只靠骨架 `normal_surprise` 演出。
- **兵蚁 / 盾蚁也没有 `death` 采样**，死亡复用 `skill2`。
- **三只精英有 `fatal` 采样但没有独立死亡采样**：处决时已播 `fatal`，
  所以把 `DeathSfxClip => null`、`HasDeathSfx => false`，避免同一次死亡响两声。

`DamageSfxType => DamageSfxType.Armor`（甲壳）保持不变 —— 受击的闷响由它决定，
和上面这些「语义采样」不冲突。

### 5.5 处决/换防演出

`normal_fatal`（3.97 s）在原始素材里是 Boss 的处决动作；本设计用它播「处决自家召唤物」。
本批把它从「只播骨架动画」升级为「骨架 + 三层全屏特效 + 敌方召唤物同步倒下」。

#### 素材转换

`effect/1001013_fatal_eff_{b,f,sub}` 三层已用
`SpineSkeletonDataConverter.exe -v 4.2.11` 转到 4.2（铁律 3），产物在
`CznMonster/animations/effects/polemica_fatal_{b,f,sub}/`，并各生成一个
`_skel_data.tres`。**PNG 保留原始文件名**（`1001013_fatal_eff_b.png` /
`1001013_fatal_eff_f.png` / `1001013_fatal_sub.png`），因为 `.atlas` 的页名就写的这个名字，
改名会断链。

各层在 `corpsleader_formica_1001013_fatal_eff.cfx` 里的 z 值：

| 层 | .cfx z | 尺寸 | 动画名 | 挂载容器 |
|---|---:|---|---|---|
| `1001013_fatal_eff_b` | −600 | 1920×640 | `animation` | `BackCombatVfxContainer`（背景之上、角色之下） |
| `1001013_fatal_eff_f` | 3 | 136×48 | `animation` | `CombatVfxContainer` |
| `1001013_fatal_sub` | 5 | 1912×440 | `normal_fatal` | `CombatVfxContainer` |

#### 为什么是两个场景

`z_index` **只在同一父节点内排序**，而 `CombatVfxContainer` 整体位于角色之上。
要让背景层落在「背景之上、角色之下」，只能挂 `BackCombatVfxContainer`；
前景两层挂 `CombatVfxContainer` 并保留 .cfx 的相对顺序（Sub 5 > EffF 3）。

- `scenes/vfx/polemica_fatal_b.tscn` → 背景层，内含 `EffB`（`z_index = 0`）
- `scenes/vfx/polemica_fatal_f.tscn` → 前景层，内含 `EffF`（`z_index = 3`）+ `Sub`（`z_index = 5`）

#### 运行时编排（`Content/Vfx/PolemicaFatalVfx.cs`）

- `Play(Creature anchor)`：先 `Clear()` 把上一次的顶掉（换防连发不会叠三份全屏特效），
  再以首领的 `VfxSpawnPosition` 为锚点同时实例化两个场景。
  取不到节点时退回 `CombatVfxContainer.GlobalPosition`；`TestMode` 下直接不播。
- 骨架异步加载，所以每层都用 `node.RunWhenSpineReady(new MegaSprite(node), ...)` 设
  `SetAnimation(<层动画名>, loop: false)`，GDExtension 边界安全。
- 三层最长的 timeline 是 4.167 s，**4.4 s 后自动 `QueueFree`**，不做节点池。
- 标定常量 `BackScale` / `FrontScale` / `BackOffset` / `FrontOffset` 目前都是 1.0 / 零，
  等 `CZN_AnimLab` 或实机微调（§10 风险表）。

#### 与处决流程的接线（`Polemica.ExecuteAdds`）

- `REBROOD` / `ELITE_REBROOD`：`ExecuteAdds()` 默认 `playVfx: true`。
- 首领与**全部**召唤物同时起手：`CreatureCmd.TriggerAnim` 跑到第一个 `await` 前是同步的，
  所以用 `Task.WhenAll` 把「首领 `Fatal`(1.5 s) + 每只召唤物
  `ExecuteAnimTrigger`」一起发出去，再等齐、最后 `CreatureCmd.Kill(adds, force: true)`。
  处决是「一拍」，不逐个播，否则 3 只召唤物会拖成 9 秒。
- 召唤物的被处决反应：精锐（岩壳虫/翼壳虫/壳虫）有 `normal_fatal` → `Fatal`；
  兵蚁/盾蚁没有 `normal_fatal` → 改用 `normal_surprise`（0.533 s）。
  每只怪通过 `PolemicaAddMonster.ExecuteAnimTrigger` / `ExecuteAnimWait` / `ExecuteSfxClip`
  自己声明，基类统一发命令。
- `SHELL`：同一回合还要「处决 + 护盾」，属于阶段转换而不是换防，
  传 `ExecuteAdds(playVfx: false)`，避免一条 4 秒全屏演出叠上 `Shell` 动画。
- **不要**在 `Kill` 之后再手动 `CombatState.RemoveCreature`：`Kill` 已按原生流程
  移除战斗状态并异步播死亡；提前摘掉会让死亡贴图不消失、悬停刷 `NullReferenceException`。

#### 不做的部分

`camera_path/*.json` 与 `node/1001013_fatal_node.json` 只作为**时序参考**：
STS2 战斗场景没有 CZN 那种自由镜头与颜色分级，无法 1:1 复刻运镜。
震屏交给原生的 `NGame.Instance?.ScreenShake(ShakeStrength, ShakeDuration)`
（`CreatureCmd` 在伤害结算时已按伤害档自动触发 Weak/Medium/Strong），不手写位移模拟。
若实机觉得处决不够「重」，可在 `Polemica.ExecuteAdds` 里补一次
`ScreenShake(ShakeStrength.Strong, ShakeDuration.Normal)` —— 原生
`CeremonialBeast` / `Vantom` 的相位转换就是这么做的，属可选项，本批未加。

#### ④ 静态头像 / 动画立绘：评估结论（**不实现**）

**素材**（`face/` 下：12 张静态 PNG + 3 套动画立绘骨架，立绘各含 1 张 PNG）：

| 位置 | 内容 | 用途 |
|---|---|---|

**为什么本批不做：**

1. **图鉴不缺这张脸。** STS2 图鉴选中怪物后实例化的是 `NCreature`，
   加载的是 `VisualsPath` 指向的**战斗 Spine**。我们 6 套战斗骨架本来就能动，
   静态头像在这个界面里没有挂载点，做了也看不见。
2. **战果页 / 地图 / 血条已经解决。** 「跑图历史图标 + 轮廓」
   （`images/ui/run_history/polemica_boss*.png`）和地图图标都已接入并在 pck 里；
   它们是 STS2 真正会读的怪物「脸」，静态 `face_mob_*` 与它们功能重叠。
3. **单怪 Mod 没有「立绘面板」。** 动画立绘（`face/portrait/*`）原本用于 CZN 的
   角色/怪物详情页、养成页；STS2 没有等价面板，要显示只能自己注入 UI 节点，
   属于本 Mod 范围之外的独立功能，而且 3 套立绘只覆盖 3 只召唤物，Boss 反而没有。
4. **成本与收益不成比例。** 3 套立绘要再走一遍 4.2.11 转换 + 写一套自定义面板
   （布局、缩放、输入遮挡、多语言、分辨率适配），换到的只是一个原版 UI 不展示的页面。

**若将来要做，最小可行路径**（记录备查，不排期）：

1. 只在「怪物 Tooltip / 图鉴列表」这类**已经有图标节点**的地方换图 ——
   用 `face_mob_10010xx.png` 替换现有 run_history 图标，成本最低；
2. 要先确认真实挂载点（`NCreatureIcon` / `NCreature` 的血条与提示组件），
   不能凭空造面板；
3. 动画立绘（`face/portrait/*`）只有在出现「需要运动立绘的界面」时才值得转，
   且必须补 Boss 自己的立绘，否则展示面不完整。

### 7.2 章节缩放 helper

```csharp
using System;

namespace CznMonster.Content.Monsters;

/// <summary>波勒米卡家族的章节缩放：让同一只 Boss 在第 1/2/3 章都能用。</summary>
internal static class PolemicaScaling
{
    /// <summary>本局该 Boss 实际出现的章节（0/1/2）。由首领替换补丁写入。</summary>
    public static int ActIndex { get; set; } = 2;

    private static readonly decimal[] HpMul = { 2m / 3m, 5m / 6m, 1m };
    private static readonly decimal[] DmgMul = { 3m / 4m, 9m / 10m, 1m };

    public static int Hp(int baseHp) => (int)Math.Floor(baseHp * HpMul[Math.Clamp(ActIndex, 0, 2)]);
    public static int Dmg(int baseDmg) => (int)Math.Floor(baseDmg * DmgMul[Math.Clamp(ActIndex, 0, 2)]);
}
```

```csharp
using System.Collections.Generic;
using System.Linq;
using System.Threading.Tasks;
using CznMonster.Content.Audio;     // CznMonsterSfx
using CznMonster.Content.Powers;
using CznMonster.Content.Vfx;       // PolemicaFatalVfx
using MegaCrit.Sts2.Core.Animation;
using MegaCrit.Sts2.Core.Audio;      // DamageSfxType
using MegaCrit.Sts2.Core.Bindings.MegaSpine;
using MegaCrit.Sts2.Core.Commands;
using MegaCrit.Sts2.Core.Entities.Ascension;
using MegaCrit.Sts2.Core.Entities.Creatures;
using MegaCrit.Sts2.Core.GameActions.Multiplayer;
using MegaCrit.Sts2.Core.Helpers;   // AscensionHelper
using MegaCrit.Sts2.Core.Models;
using MegaCrit.Sts2.Core.Models.Powers;
using MegaCrit.Sts2.Core.MonsterMoves.Intents;
using MegaCrit.Sts2.Core.MonsterMoves.MonsterMoveStateMachine;
using MegaCrit.Sts2.Core.ValueProps;

namespace CznMonster.Content.Monsters;

public sealed class Polemica : MonsterModel
{
    // ── 数值（第 3 章基准，升华值见括号；再乘章节系数） ──
    private int AttackDamage => PolemicaScaling.Dmg(AscensionHelper.GetValueIfAscension(AscensionLevel.DeadlyEnemies, 32, 30));
    private int HeavyDamage  => PolemicaScaling.Dmg(AscensionHelper.GetValueIfAscension(AscensionLevel.DeadlyEnemies, 26, 24));
    private int BlockAmount  => PolemicaScaling.Dmg(AscensionHelper.GetValueIfAscension(AscensionLevel.DeadlyEnemies, 50, 45));

    // ── 状态 ──
    private bool _summonedOnce;      // 对应 cs02_0338 ≥ 1
    private int  _brood;             // 对应 cs02_0339（0..3）

    public override int MinInitialHp => PolemicaScaling.Hp(AscensionHelper.GetValueIfAscension(AscensionLevel.ToughEnemies, 475, 450));
    public override int MaxInitialHp => MinInitialHp;
    public override DamageSfxType TakeDamageSfxType => DamageSfxType.Armor;

    // 视觉场景走引擎约定路径（与 CznHeidemarie 一致）
    protected override string VisualsPath => "res://scenes/creature_visuals/polemica.tscn";

    // 音效：占位路径由 CznMonsterSfx 补丁解析成本地 ogg（§5.4）
    protected override string AttackSfx => CznMonsterSfx.Placeholder(this, "skill1_3");
    public override string DeathSfx     => CznMonsterSfx.Placeholder(this, "death");
    public override string? HurtSfx     => CznMonsterSfx.Placeholder(this, "hurt");

    private int LivingAdds => CombatState.GetTeammatesOf(Creature)
        .Count(c => c != Creature && c.IsAlive);

    protected override MonsterMoveStateMachine GenerateMoveStateMachine()
    {
        // ── 9 个行动 ──
        var broodCall   = new MoveState("BROOD_CALL_MOVE", BroodCallMove, new SummonIntent(), new BuffIntent());
        var legionCharge= new MoveState("LEGION_CHARGE_MOVE", LegionChargeMove, new SingleAttackIntent(AttackDamage), new BuffIntent());
        var soloStrike  = new MoveState("SOLO_STRIKE_MOVE", SoloStrikeMove, new SingleAttackIntent(HeavyDamage));
        var rebrood     = new MoveState("REBROOD_MOVE", RebroodMove, new SummonIntent());
        var shell       = new MoveState("SHELL_MOVE", ShellMove, new DefendIntent());
        var eliteHatch  = new MoveState("ELITE_HATCH_MOVE", EliteHatchMove, new SummonIntent(), new BuffIntent());
        var eliteRebrood= new MoveState("ELITE_REBROOD_MOVE", EliteRebroodMove, new SummonIntent());
        var secondWind  = new MoveState("SECOND_WIND_CHARGE_MOVE", SecondWindChargeMove, new SingleAttackIntent(AttackDamage), new BuffIntent());
        var finalStrike = new MoveState("FINAL_STRIKE_MOVE", FinalStrikeMove, new SingleAttackIntent(HeavyDamage));

        // ── P1 / P3 / P5 / P7 四个条件分支（顺序即优先级） ──
        var p1 = new ConditionalBranchState("P1_BRANCH");
        p1.AddState(soloStrike, () => _summonedOnce && LivingAdds == 0);
        p1.AddState(rebrood,    () => _brood >= PolemicaBroodPower.Threshold);
        p1.AddState(shell,      () => Creature.GetHpPercentRemaining() < 0.5);
        p1.AddState(legionCharge, () => true);

        var p3 = new ConditionalBranchState("P3_BRANCH");
        p3.AddState(rebrood,  () => _brood >= PolemicaBroodPower.Threshold);
        p3.AddState(broodCall,() => LivingAdds >= 2);
        p3.AddState(shell,    () => Creature.GetHpPercentRemaining() < 0.5);
        p3.AddState(soloStrike, () => true);

        var p5 = new ConditionalBranchState("P5_BRANCH");
        p5.AddState(finalStrike,  () => LivingAdds == 0);
        p5.AddState(eliteRebrood, () => _brood >= PolemicaBroodPower.Threshold);
        p5.AddState(secondWind,   () => true);

        var p7 = new ConditionalBranchState("P7_BRANCH");
        p7.AddState(eliteRebrood, () => _brood >= PolemicaBroodPower.Threshold);
        p7.AddState(secondWind,   () => LivingAdds >= 2);
        p7.AddState(finalStrike,  () => true);

        // ── 连线 ──
        broodCall.FollowUpState   = p1;
        legionCharge.FollowUpState= p1;
        soloStrike.FollowUpState  = p3;
        rebrood.FollowUpState     = p1;
        shell.FollowUpState       = eliteHatch;   // P4 只停 1 回合
        eliteHatch.FollowUpState  = p5;
        secondWind.FollowUpState  = p5;
        eliteRebrood.FollowUpState= p5;
        finalStrike.FollowUpState = p7;

        var states = new MonsterState[]
        {
            broodCall, legionCharge, soloStrike, rebrood, shell,
            eliteHatch, eliteRebrood, secondWind, finalStrike, p1, p3, p5, p7
        };
        return new MonsterMoveStateMachine(states, broodCall);   // 开场：军团召集
    }

    // ── 行为实现 ──

    private async Task BroodCallMove(IReadOnlyList<Creature> targets)

    private async Task SoloStrikeMove(IReadOnlyList<Creature> targets)
    {
        await DamageCmd.Attack(HeavyDamage).FromMonster(this)

            .WithHitFx("vfx/vfx_attack_blunt")
            .Execute(null);

    private async Task RebroodMove(IReadOnlyList<Creature> targets)

    private async Task ShellMove(IReadOnlyList<Creature> targets)

    private async Task EliteHatchMove(IReadOnlyList<Creature> targets)
    {
        await CreatureCmd.TriggerAnim(Creature, "Summon", 2.43f);

        await SummonWave2();
        await AddBrood(1);
    }

    private async Task EliteRebroodMove(IReadOnlyList<Creature> targets)
    {
        int executedCount = await ExecuteAdds();
        if (executedCount > 0)
        {
            await PowerCmd.Apply<StrengthPower>(

    private async Task SecondWindChargeMove(IReadOnlyList<Creature> targets)
    {
        await DamageCmd.Attack(AttackDamage).FromMonster(this)
            .WithAttackerAnim("AttackHeavy", 1.70f)
            .WithAttackerFx(null, CznMonsterSfx.Placeholder(this, "skill1_3"))
            .WithHitFx("vfx/vfx_attack_blunt")
            .Execute(null);
        await PowerCmd.Apply<StrengthPower>(new ThrowingPlayerChoiceContext(),
            CombatState.GetTeammatesOf(Creature), 1m, Creature, null);
        await AddBrood(1);

    private async Task FinalStrikeMove(IReadOnlyList<Creature> targets)
    {

            .WithAttackerAnim("AttackFast", 1.03f)
            .WithAttackerFx(null, CznMonsterSfx.Placeholder(this, "skill4"))
            .WithHitFx("vfx/vfx_attack_blunt")
            .Execute(null);
        await AddBrood(1);

    // ── 召唤/处决/计数 helper ──

    private async Task SummonWave1()
    {
        await SummonOne<PolemicaLegionSoldier>();
        await SummonOne<PolemicaLegionShield>();
        await SummonOne<PolemicaLegionSoldier>();
    }

    private async Task SummonWave2()
    {
        await SummonOne<PolemicaRockShellInsect>();
        await SummonOne<PolemicaWingShellInsect>();
        await SummonOne<PolemicaShellInsect>();
    }

    private string? FindFreeSlot()
    {
        // 不能直接用 Encounter.GetNextSlot：它只比对 SlotName、不看 IsAlive，
        // 行动计数中断在玩家回合内时，刚死但未清理的召唤物会占着槽位。
        EncounterModel? enc = CombatState.Encounter;
        if (enc == null) return null;
        foreach (string slot in enc.Slots)
        {
            bool occupied = CombatState.Enemies.Any(c => c.SlotName == slot && c.IsAlive);
            if (!occupied) return slot;
        }
        return null;
    }

    private async Task SummonOne<T>() where T : MonsterModel
    {
        string? slot = FindFreeSlot();
        if (string.IsNullOrEmpty(slot)) return;                  // 槽位满：不召
        // MinionPower 由 PolemicaAddMonster.AfterAddedToRoom 统一挂载
        await CreatureCmd.Add<T>(CombatState, slot);
    }

    // playVfx=false 用于 SHELL 回合（同一回合还要播 Shell，不叠 4 秒全屏特效，§5.5）
    private async Task<int> ExecuteAdds(bool playVfx = true)
    {
        List<Creature> adds = CombatState.GetTeammatesOf(Creature)
            .Where(c => c != Creature && c.IsAlive).ToList();
        if (adds.Count == 0) return 0;

        if (playVfx) PolemicaFatalVfx.Play(Creature);          // 三层全屏特效（§5.5）
        CznMonsterSfx.Play(this, "fatal");

        // 首领 + 全部召唤物同时起手（TriggerAnim 到首个 await 前是同步的）
        Task bossAnim = CreatureCmd.TriggerAnim(Creature, "Fatal", 1.5f);
        List<Task> addAnims = new(adds.Count);
        foreach (Creature add in adds)
        {
            if (add.Monster is not PolemicaAddMonster model) continue;
            if (model.ExecuteSfxClip is { } clip) CznMonsterSfx.Play(model, clip);
            addAnims.Add(CreatureCmd.TriggerAnim(add, model.ExecuteAnimTrigger, model.ExecuteAnimWait));
        }
        await Task.WhenAll(addAnims);
        await bossAnim;

        await CreatureCmd.Kill(adds, force: true);
        // 不要再手动 CombatState.RemoveCreature：Kill 已按原生流程清理，
        // 提前摘掉会让死亡贴图不消失、悬停刷 NullReferenceException。
        return adds.Count;
    }

    private async Task AddBrood(int amount)
    {
        _brood = System.Math.Min(PolemicaBroodPower.Threshold, _brood + amount);
        PolemicaBroodPower? power = Creature.GetPower<PolemicaBroodPower>();
        if (power == null)
            await PowerCmd.Apply<PolemicaBroodPower>(new ThrowingPlayerChoiceContext(), Creature, _brood, Creature, null);
        else
            power.SetAmount(_brood);
    }

    private async Task ResetBrood()
    {
        _brood = 0;
        await PowerCmd.Remove<PolemicaBroodPower>(Creature);
    }

    // ── 动画：CZN 的 normal_* 名与游戏默认名不同，必须 override ──
    // 引擎不发 "Spawn" 触发器，登场动画必须是初始状态（见 §5.3 勘误）
    public override CreatureAnimator GenerateAnimator(MegaSprite controller)
    {
        var idle   = new AnimState("normal_idle", isLooping: true);
        var enter  = new AnimState("normal_enter")    { NextState = idle };
        var hit    = new AnimState("normal_hit")      { NextState = idle };
        var groggy = new AnimState("normal_groggy")   { NextState = idle };
        var dead   = new AnimState("normal_death");
        var heavy  = new AnimState("normal_skill1_3") { NextState = idle };
        var fast   = new AnimState("normal_skill4")   { NextState = idle };
        var summon = new AnimState("normal_skill2_3") { NextState = idle };
        var shell  = new AnimState("normal_skill3")   { NextState = idle };
        var fatal  = new AnimState("normal_fatal")    { NextState = idle };

        var animator = new CreatureAnimator(enter, controller);   // 初始状态 = 登场
        animator.AddAnyState("AttackHeavy", heavy);
        animator.AddAnyState("AttackFast", fast);
        animator.AddAnyState("Summon", summon);
        animator.AddAnyState("Shell", shell);
        animator.AddAnyState("Fatal", fatal);
        // 先加带条件的眩晕分支，再加默认 Hit（AnimState 按插入顺序取第一个成立的分支）
        animator.AddAnyState("Hit", groggy, () => Creature.IsStunned);
        animator.AddAnyState("Hit", hit);
        animator.AddAnyState("Dead", dead);
        return animator;
    }

    protected override bool ShouldShowMoveInBestiary(string moveStateId)
        => moveStateId is not ("REBROOD_MOVE" or "ELITE_REBROOD_MOVE" or "SHELL_MOVE");
}
```

> 注意：`AddBrood` 里 `PowerCmd.Apply` 传入的是 `_brood`（当前值），
> 首次挂载时直接显示 1/2/3；之后用 `SetAmount` 同步（参考上游 §7.7 的做法）。
> 如果希望每次 +1 都走命令队列，可改为 `Apply(... 1m ...)` 再读 `Amount`。
>
> **落地时的四处必要修正**（骨架代码里已体现，与上面的设计代码有差异）：
> 1. `EncounterModel.GetNextSlot` 只比对 `SlotName`、不检查 `IsAlive`，行动计数中断在
>    玩家回合内时，刚死但尚未清理的召唤物会占着槽位。实现改用 `FindFreeSlot()`，
>    只把「存活且 SlotName 相同」的单位视为占用。
> 2. `ExecuteAdds` **不要**在 `CreatureCmd.Kill(..., force: true)` 之后手动
>    `CombatState.RemoveCreature` —— 早期草案曾这么写，实测会让死亡贴图不消失、
>    悬停刷 `NullReferenceException`；`Kill` 本身已按原生流程清理战斗状态。
> 3. `MinionPower` 统一在 `PolemicaAddMonster.AfterAddedToRoom` 挂载，`SummonOne` 不重复添加。
> 4. 音效不再是 `SfxCmd.Play("event:/sfx/...")`，而是
>    `CznMonsterSfx.Placeholder` + 补丁（§5.4）；处决演出加了三层全屏特效（§5.5）。

### 7.5 召唤物基类与三个精英

```csharp
using System.Threading.Tasks;
using MegaCrit.Sts2.Core.Commands;
using MegaCrit.Sts2.Core.GameActions.Multiplayer;
using MegaCrit.Sts2.Core.Models;
using MegaCrit.Sts2.Core.Models.Powers;

namespace CznMonster.Content.Monsters;

/// <summary>波勒米卡召唤物的公共基类：统一挂 MinionPower、统一不进图鉴，
/// 并把音效与处决表现收口（§5.3 / §5.4 / §5.5）。</summary>
public abstract class PolemicaAddMonster : MonsterModel
{
    public override bool ShouldShowInCompendium => false;

    protected override string AttackSfx => CznMonsterSfx.Placeholder(this, "skill1");

    public override bool HasDeathSfx => DeathSfxClip != null;
    protected virtual string? DeathSfxClip => "death";

    public virtual string ExecuteAnimTrigger => "Fatal";
    public virtual float  ExecuteAnimWait    => 1.5f;
    public virtual string? ExecuteSfxClip    => "fatal";

    // 召唤登场采样 clip（兵蚁盾蚁复用 enter 采样）
    public virtual string EntranceSfxClip => "enter";

    public override async Task AfterAddedToRoom()
    {
        await base.AfterAddedToRoom();
        CznMonsterSfx.Play(this, EntranceSfxClip);      // 登场动画是初始状态，音效在这里补
        await PowerCmd.Apply<MinionPower>(new ThrowingPlayerChoiceContext(), Creature, 1m, Creature, null);
    }
```

## 11. 疑问与建议

> 以下每条都是「疑问 + 建议」；未裁决前按建议值实现，改动只影响数值表或一张映射表，不动结构。

### Q1 5 只召唤物的中文名缺失

**疑问**：包内只有 `1001019=rock_shell_insect`、`1001018=wing_shell_insect`、
`1001004=shell_insect` 三个代号，`1001009/1001010` 连代号都没有；本地化文本由服务器下发，
无法从素材还原正式中文名。

**建议**：先用「军团兵蚁 / 军团盾蚁 / 岩壳虫 / 翼壳虫 / 壳虫」，
在 `localization/zhs/monsters.json` 里集中管理；拿到官方名后只改 JSON，不动代码。

### Q2 `cs00_0002 / 0003 / 0007` 的真实语义

**疑问**：三者的 `link_cs_id` 只出现在「攻击 + 减益」卡上，包内没有名称/图标/描述，
无法确定哪个是虚弱、脆弱、易伤、中毒或出血。

**建议**：按「三只精英各给一种经典减益」的最稳映射：
`1001004→虚弱(Weak)`、`1001019→脆弱(Frail)`、`1001018→易伤(Vulnerable)`，
兵蚁的 `cs00_0007` 沿用易伤。若后续拿到官方文本，只需改 §4.7 的 3 个 `PowerCmd.Apply` 泛型。

### Q3 护盾 `SHIELD_ATTR_AUTO` 是否跨回合

**疑问**：`pt4_00/pt4_10` 的 300 护盾带 `SHIELD_ATTR_AUTO`，无法确认是否「不随回合衰减」；
STS2 的格挡在生物回合开始清零（`Creature.cs:696`）。另外三只精英共享的登场卡
`1001019_01_pt1_00` 会给自身 +5 `cs02_0091`，也疑似「壳甲」类防御层。

**建议**：v1 用普通格挡 45（P4 只停留 1 回合，语义足够接近）；
若确认原版护盾跨回合，改为 `PlatingPower`（每回合自动补）或 `BarricadePower`（不清格挡）。
精英的 `cs02_0091` v1 不实现；若精英太脆，再补 5 格挡或 5 层 `PlatingPower`。

### Q4 「处决其他怪」的目标到底是哪边

**疑问**：`SKILL_EFF_KILL` 的 `TARGET_UNIT_ALL_ENEMY_EXCEPT_CASTER` 如果按「Boss 的敌人」
理解就是秒杀玩家，显然不成立；按「除自己以外的己方」理解才是换防。

**建议**：采用「按说话者阵营的全体」语义：伤害指向玩家，增益/护盾/处决指向己方。
本设计已按此实现（§2.6）。若后续发现原版其实是「献祭一只小怪回血」，只需在 `ExecuteAdds`
后补一个 `CreatureCmd.Heal`，不影响结构。

### Q5 P2 / P6 在原数据中不可达，是否要补全

**疑问**：`0339` 只在 `pt1_01` +1，而 `pt1_01` 只在 `0338==0` 时可用，`0338` 又被自己 +2；
所以 `0339==3` 永远不成立，P2/P6 是死内容（§2.2）。

**建议**：把「仪式」改成**每次 Boss 行动 +1、满 3 换防**（本设计采用）。
这样 P2/P6 变成每 3 拍一次的换防循环，既保留「三拍召集」的意图，又让第二阶段有节奏。
若要 100% 忠实原数据，则删掉 `REBROOD/ELITE_REBROOD` 与仪式 Power，
但后半场会退化成「P5 召一次精英 → P7 打到死」，内容明显变少。

### Q6 CZN 语音 bank 怎么处理

**疑问**：`sound/monster_1001013.bank` 是 FMOD bank，STS2 的事件路径是 `event:/sfx/...`，
两者不是同一种资源；`tools/extract_fmod_bank.py` 能提取，但需要重建 event 或直接播放 wav。

**建议**：v1 全部用原生占位音效（§5.4），先保证不 404；v2 再评估「提取 wav + 自建 bank」
或「用 `AudioStreamPlayer` 直接播 wav」。语音不是本次验收的阻塞项。

**裁定**：`tools/extract_fmod_bank.py` 提取，**但不重建 bank** ——
6 个 bank 共 28 条采样直接导成 ogg，由 `CznMonsterSfx` + `SfxCmd` 前缀补丁播放（§5.4）。
**已落地**（2026-10-20）。

### Q7 处决特效 / 运镜是否要做

**疑问**：`effect/1001013_fatal_eff_b/f/sub` 三层 + `camera_path` + `node` 是完整的处决演出，
但 STS2 战斗场景没有相机、没有颜色分级，`node` 时序也无法直接复用。

**建议**：v1 只用 `normal_fatal` 动画 + `CreatureCmd.Kill`，不做全屏；
v2 若要做，按上游手册 §5 的方式把三层特效挂到 `CombatVfxContainer`，
镜头用 `NCombatRoom` 的容器位移模拟，不追 1:1。

**裁定**：**做特效，不做运镜。** 三层转 4.2.11 后拆两个场景
（背景层 `polemica_fatal_b.tscn` 挂 `BackCombatVfxContainer`，前景两层
`polemica_fatal_f.tscn` 挂 `CombatVfxContainer`），三层同时起播、4.4 s 自动释放；
`camera_path/*.json` 与 `node/*.json` 只当**时序参考**，震屏交给原生
`NGame.ScreenShake`（§5.5）。**已落地**（2026-10-20）；
缩放/偏移待 `CZN_AnimLab` 与实机标定。

### Q8 Boss HP 是否要按原比例 1:1

**疑问**：按「精英 68% = 100 HP」锚点，Boss 是 450；若按「小怪 27% = 70 HP」锚点，
Boss 会到约 790 HP，战斗会非常长。

**建议**：采用 450（升华 475）。RANK_S 的压迫感靠「召唤 + 力量雪球 + 换防」体现，
不靠血牛；若实测偏短，优先加召唤物 HP/攻击，而不是加 Boss HP。

### Q9 `1001009` 的 `stance1` 姿态要不要实现

**疑问**：`1001009_stance1.srcs` 存在，且 `model_setting` 列了 `stance1_*` 动画；
但 Boss 的召唤卡没有「切换姿态」指令，原版可能是血量/条件触发的第二形态。

**建议**：v1 不实现姿态切换，只使用 `normal_*`；如果后续要加「兵蚁半血变姿态1」，
在 `PolemicaLegionSoldier` 里 override `GenerateAnimator`，用 `HasPower`/`HpPercent` 选动画即可。

### Q10 岩壳虫 +4 力量是否过强

**疑问**：原始 `cs00_0001 +4` 是真实数据，但 STS2 的力量是线性叠加，且岩壳虫每 3 回合就能再叠一次；
配合 Boss 的全体 +1，后期单次 18 伤害可能涨到 30+。

**建议**：先按 +4 实现并实测 T6/T7；若第 3 章玩家在精英波减员明显，改为 +3，
并在 `§8.2` 表里同步。不要直接砍半，否则「岩壳硬化」这个招牌动作会失去威胁。

### Q11 是否接受把 CznMonster 从纯 dll 升级为 dll + pck

**疑问**：`CznMonster.json` 目前是 `has_pck: false`，`build.ps1` 也明确写着「本 mod 没有
Spine / 场景 / 音频资源，不需要 Godot --import / --export-pack」。本设计要使用 CZN 的
Spine 骨架、6 个视觉场景、1 个遭遇槽位场景、能力图标，这些都必须进 pck；
升级会引入 Godot 4.5.1 导出链路、`export_presets.cfg`、`bin/spine_godot_extension.gdextension`
和更长的构建时间。

**建议**：接受升级，按 §5.0 的四件套改造；这是使用 CZN 原素材的唯一可行路径。
若想先验证数值，可先做一版「复用原生怪物视觉 + 纯 dll」的灰盒版（把 `VisualsPath` 指到
原生 `creature_visuals/...`），但灰盒版不能作为最终交付。

### Q12 岩壳虫「弃光手牌」是否过强

**疑问**：`1001019_01_pt1_11` 的 `SKILL_EFF_CARD_MOVE_TO`（`CARD_SET_ALL` → `CARD_PLACE_DISCARD`）
只能推断为「把玩家手牌全部弃掉」；在 STS2 里这等于让玩家空过一回合，
若三只精英同时在场、且循环里连续触发，体验会非常差。

**建议**：v1 保留「弃光手牌」但加硬冷却（同一只岩壳虫 3 回合内不再使用）；
实测若仍然过强，改为「随机弃 2 张」。改法只动 `RockHardenMove` 里的
`CardCmd.Discard` 参数与分支冷却，不动其它结构。

### Q13 召唤物基础伤害是否过高

**疑问**：§3.1 按「200% ≈ 30」锚点换算出 100% 档 15、150% 档 22；这是按**单体伤害**
对齐的，没有按「同一波最多 3 只同回合行动」做总量折扣。结果第一波
（兵蚁×2 + 盾蚁，三张攻击拍全在 100% 档）同回合总输出 33 > Boss 单发 22；
且兵蚁战吼突刺给全队 +1 力量（两只独立掷骰，连用上限 2，一回合最多 +4），
配合 Boss 冲锋的全队 +1，滚雪球没有约束。

**结论**：确实过强。平衡调整将 100% 档 15 → 12（升华 13）、150% 档 22 → 18（升华 20），
落点见 §3.1 实装表；换防 / 掩护 / 防御拍的 6 / 9 档与 Boss 的 30 / 24 档不动。
第 1 / 2 章由 `PolemicaScaling` 的章节系数继续缩放（12 × 3/4 = 9，18 × 3/4 = 13）。
若实测仍偏强，下一档优先砍「兵蚁 Rally 连用上限 2 → 1」而不是再降伤害，
理由：伤害下调影响所有回合，连用上限只削滚雪球的斜率。
