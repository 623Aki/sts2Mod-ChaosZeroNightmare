### 1.3 勘误：`.srcs` 不是骨架

`_filelist.txt` 写「`.srcs` Spine 骨架文件（.skel 二进制）」，但实测：

- `model_data/1001013.srcs` 的字节头是文本 JSON；
- 内容是 `command_sets`：把 `m_attack_01_1` / `buff_1_1` 等**动作指令**映射到
  `normal_skill4` / `normal_skill2_3` 等**骨架动画名**；
- 真正的骨架是 `model/<ID>.json`（Spine 3.8.79 工程，含 animations）。

**结论**：转 4.2.11 要对 `model/<ID>.json` 做转换，不能把 `.srcs` 改名成 `.skel`。

## 2. 原始机制解构

### 2.1 七阶段状态机（原文）

来源：`db/monster(invader)@monster_pattern_set.json` 与 `行动轨迹与切换条件.txt`。

| 阶段 | pattern | 条件 0 | 条件 1 | 条件 2 | 进入动作 |
|---|---|---|---|---|---|
| P1 | `pt1` | `0338≥1 且 存活怪==1` → P3 | `0339==3` → P2 | `HP%<50` → P4 | `pt1_01`（召集 + 强化） |
| P2 | `pt2` | 1 回合计时器 → P1 | `HP%<50` → P4 | — | `pt2_00`（重置计数） |
| P3 | `pt3` | `0339==3` → P2 | `存活怪≥2` → P1 | `HP%<50` → P4 | `pt3_00`（重置 0337） |
| P4 | `pt4` | 1 回合计时器 → P5 | — | — | `pt4_00`（处决小怪 + 护盾） |
| P5 | `pt5` | `存活怪==1` → P7 | `0339==3` → P6 | — | `pt5_01`（被动：召集精英） |
| P6 | `pt6` | 1 回合计时器 → P5 | — | — | `pt6_00`（重置计数） |
| P7 | `pt7` | `0339==3` → P6 | `存活怪≥2` → P5 | — | 无专属卡；卡池指向 `pt3_10` |

> 条件按 0→1→2 的顺序判定，**顺序有意义**（例如 P5 先判「无小怪→P7」，再判「0339==3→P6」）。

### 2.2 阶段可达性分析（重要发现）

把状态效果与卡牌可用条件对齐后，按**可见 DB** 推断原数据里的 P2 / P6 **不可达**：

1. `0339`（换防计数）在可见 DB 里**只有** `pt1_01` 会 +1；
2. `pt1_01` 的可用条件是 `cd_icre_ics_mon_0695_eq00`，即 **`0338 == 0`**；
3. `pt1_01` 自身会 `0338 +2`，而 `0338` 只有 `pt4_10`（P4 护盾）会清零；
4. P1 再次进入时 `0338` 仍是 2，`pt1_01` 不可用 → `0339` 无法再增加；
5. 因此 `0339` 最多到 1，`0339==3` 永远不成立 → **P2、P6 是死内容**；
6. P7 没有任何召唤卡，一旦进入 P7 就不可能满足「存活怪≥2→P5」，所以 P7 是最终攻击循环。

**原数据实际可玩到的流程**：

```
P1（召唤一波 + 攻击） → 小怪死光 → P3（单体攻击）
   → HP<50% → P4（处决小怪 + 护盾，1 回合） → P5（召唤精英 + 攻击）
   → 精英死光 → P7（终局攻击循环直到死亡）
```

**本设计的处理**：保留「3 拍换防」的设计意图，用一个可达的「孵化仪式」计数器替代
`0339`，让 P2 / P6 作为**换防动作**在每个循环的第 3 拍触发（§4.4/§4.5，见 §11 Q5）。
这是本文对原数据最大的一处**有意偏离**。

**目标语义判读**：`SKILL_EFF_KILL` 的目标是 `TARGET_UNIT_ALL_ENEMY_EXCEPT_CASTER`。
如果把它理解成「Boss 的敌人 = 玩家」，就会得出「秒杀玩家」的荒谬结论；
结合 `pt2_10/pt4_00/pt6_10` 的「换防」语境，唯一自洽的读法是：
**「除自己以外的己方单位」= 场上的召唤物**。因此本文把 `ALL_ENEMY` 一律按
「按说话者阵营的全体」处理：伤害类指向玩家，增益/护盾/处决类指向己方。
（这是全篇最重要的一条语义假设，见 §11 Q4。）

## 3. 数值换算规则（CZN → STS2）

### 3.1 伤害：`STS = round(CZN% × 0.15)`

以「Boss 主攻击 200% ≈ 第 3 章首领的一次重击 30」为锚点，得攻击力基准 15。

| CZN 百分比 | 200% | 160% | 150% | 100% | 60% | 40% |
|---|---|---|---|---|---|---|
| STS2 换算 | 30 | 24 | 22 | 15 | 9 | 6 |
| 实装（平衡后） | 30 | 24 | **18** | **12** | 9 | 6 |

> **平衡调整（§11 Q13）**：按换算值直落 15/22 时，第一波（兵蚁×2 + 盾蚁）同回合
> 总输出 33 > Boss 单发 22，且兵蚁 Rally 给全队 +1 力量无上限约束，滚雪球过强。
> 实装将 100% 档 15 → 12（升华 13）、150% 档 22 → 18（升华 20）：
> 第一波总输出 24 + 4~12，落在 Boss 一次冲锋 / 突刺的上下；150% 精英攻击档同比例下调。

升华「致命敌人」：全表 +2 / +2 / +2 / +1 / +1 / +1（与原生命中约 +7% 一致）；
平衡调整后的 18 / 12 档沿用 +2 / +1 的绝对增量。

### 3.2 生命：以「精英 68% = 100 HP」为锚点

5 只召唤物共享同一基准，取精英中值 68% 对应 100 HP，得 `1% ≈ 1.47 HP`：

| 对象 | CZN HP% | 公式 | 设计值（min–max） |
|---|---|---|---|
| 波勒米卡 | 302–315 | ×1.47 | **444–463 → 450（升华 475）** |
| 军团兵蚁 `1001009` | 25–27 | ×1.47 | 37–40 → **38（升华 40）** |
| 军团盾蚁 `1001010` | 28–30 | ×1.47 | 41–44 → **42（升华 44）** |
| 岩壳虫 `1001019` | 65–72 | ×1.47 | 96–106 → **102（升华 108）** |
| 翼壳虫 `1001018` | 65–72 | ×1.47 | 96–106 → **96（升华 101）** |
| 壳虫 `1001004` | 65–72 | ×1.47 | 96–106 → **105（升华 111）** |

> 450 落在原生第 3 章首领之上，与 RANK_S 的「超级首领」定位一致，但不至于变成
> 700+ 的血牛。若坚持按原比例 1:1 换算，Boss 会到约 790 HP，不建议（§11 Q8）。

### 3.3 格挡/护盾

`STS = round(CZN_SH × 0.15)`：

| 原始 | 出现位置 | 设计值 |
|---|---|---|
| 300 | `pt4_00` / `pt4_10` | **45 格挡**（升华 50） |
| 100 | `1001010` 全体、`1001019` 自身 | **15 格挡**（升华 17） |

> `SHIELD_ATTR_AUTO` 是否「不随回合衰减」无法从包内确认；STS2 的格挡在生物回合开始清零
>（`Creature.cs:696`），恰好让 P4 成为一个「只挡一回合」的防御拍。若确认原版护盾跨回合，
> 改用 `BarricadePower` 或 `PlatingPower`（§11 Q3）。

### 3.4 层数（力量/减益）

| 原始 | 设计值 | 说明 |
|---|---|---|
| `cs00_0001 +1`（Boss 攻击后全体） | **力量 +1** | 保留 |
| `cs00_0001 +1`（兵蚁攻击后全体） | **力量 +1** | 保留；换防会按被处决的召唤物数量继续增益 |
| `cs00_0001 +4`（岩壳虫自 buff） | **力量 +4** | 保留原值；若实测过强改 +3（§11 Q10） |
| `cs00_0001 -2`（换防） | **力量 +2 × 被处决数量** | 有意改为处决收益 |
| `cs00_0002/0003/0007 +2` | **2 层对应减益** | 映射见 §11 Q2 |
| `cs00_0007 +1` | **1 层对应减益** | 同上 |

### 3.5 连用上限 → `MoveRepeatType`

| 原始 `card_cont_use_limit` | STS2 |
|---|---|
| 2 | `AddBranch(state, maxRepeats: 2, weight)` |
| 1 | `AddBranch(state, MoveRepeatType.CannotRepeat, weight)` |
| 空（精英） | 用冷却/固定循环，见 §4.7 |

### 3.6 章节缩放（随机模式必须）

上游契约允许 CZN 首领出现在第 1–3 章。同一套 450 HP 放在第 1 章会过强，
因此按章节乘系数（先取升华值，再乘章节系数，向下取整）：

| 章节 | HP | 伤害 | 格挡 |
|---|---|---|---|
| 第 1 章（index 0） | ×2/3 | ×3/4 | ×3/4 |
| 第 2 章（index 1） | ×5/6 | ×9/10 | ×9/10 |
| 第 3 章（index 2） | ×1 | ×1 | ×1 |

结果示例（Boss）：`300 / 375 / 450` HP，`22 / 27 / 30` 主攻击，`18 / 21 / 24` 重击，
`33 / 40 / 45` 格挡。召唤物同理：兵蚁 `25 / 31 / 38`，岩壳虫 `68 / 85 / 102`。

> 实现用 `PolemicaScaling.ActIndex` 静态值（由首领替换补丁在选中该 Boss 时写入），
> `MinInitialHp` / 伤害 getter 都读它；读档后在遭遇 `GenerateMonsters` 里按当前
> RunState 兜底一次。

### 3.7 多人

- 生命：走原生 `Creature.ScaleMonsterHpForMultiplayer`（`CombatState.cs:242`），
  自定义值语义为「单人血量」。
- **伤害/格挡/层数不缩放**（原生也只缩放 HP）。
- 召唤数量固定 3（不随玩家数增加）；否则 4 人局会有 12 只小怪。
- 计数：Boss 的仪式阈值固定 3，不随玩家数变化。

### 4.2 遭遇与槽位

```csharp
public sealed class PolemicaBoss : EncounterModel, ICznMonsterEncounter
{
    public int TargetActIndex => 2;                       // 默认第 3 章
    public override RoomType RoomType => RoomType.Boss;
    public override bool HasScene => true;                // 必须：给 4 个单位定位
    public override bool FullyCenterPlayers => false;     // 玩家留在左侧（参考女皇）
    public override IReadOnlyList<string> Slots => new[] { "add1", "add2", "boss", "add3" };
}
```

- **槽位顺序**决定 `EncounterModel.GetNextSlot` 的填充顺序：Boss 占 `boss`，
  召唤物依次填 `add1 → add2 → add3`。
- `HasScene = true` 时，场景路径被写死为
  `res://scenes/encounters/polemica_boss.tscn`（`EncounterModel.cs:181`，非 virtual），
  必须由 mod 的 pck 提供该路径。
- 场景根为 `Control`，内含 4 个 `Marker2D`（坐标按 1920×1080 设计，运行时会整体减去中心）：

| Marker | 坐标 | 用途 |
|---|---|---|
| `add1` | `(780, 740)` | 左前召唤位（兵蚁） |
| `add2` | `(1030, 706)` | 中间偏后（盾蚁，最宽 236） |
| `add3` | `(1280, 740)` | 右前，离 Boss 最近（兵蚁） |
| `boss` | `(1650, 695)` | Boss 站位（最右、略靠后） |

- **间距是手算的，引擎不会替你排**：带槽位的遭遇走
  `NCombatRoom.PositionCreaturesWithSlots()`（`NCombatRoom.cs:315`，召唤物走 `:546`），
  只是把节点吸到 Marker 的全局坐标，没有 `PositionEnemies()` 那套按包围盒累加的算法。
  取值规则：`中心距 ≥ 半宽A + 半宽B + 30~40`（原版同尺寸小怪的习惯间隙）。
  当前小怪半宽 92 / 118 / 85，Boss 半宽 258.5 → 实际间隙 40 / 40 / 20。
- **Boss 视觉 0.95 → 0.85**：`polemica.tscn` 的 `Visuals.scale` 改小后，
  `Bounds`、`CenterPos` / `IntentPos` / `TalkPos` 必须同比例缩，否则点击框、意图
  和演出锚点会与画面错位。
- **屏幕换算**：`屏幕x = 960 + (markerX − 960) × 0.82`（`CombatSceneContainer`
  的 pivot 是 960,540）。Boss 包围盒右边界别超过 ~1900，超过会在开场触发
  `AdjustCreatureScaleForAspectRatio()` 把整个敌人容器缩一次并左移；而且它只在
  开场和窗口尺寸变化时跑，**召唤时不会重排**。
- 三个槽位 y 差 34px 是刻意错位（原版 `exoskeletons_normal` 也是 705/737/724），
  但**别靠 y 做前后遮挡**：敌人节点没有按 y 排序的 z，绘制顺序 = 加入顺序。
- `FullyCenterPlayers = false` + `GetCameraScaling() => 0.82f` +
  `GetCameraOffset() => Vector2.Down * 35f`（以实际包围盒在实机里微调）。
- 召唤找槽不能直接用 `Encounter.GetNextSlot`：它只比对 `SlotName`、不看 `IsAlive`，
  刚死未清理的召唤物会占位。设计上改为「存活且槽名相同才算占用」（`FindFreeSlot`）。

### 4.3 阶段机（原 7 阶段 → STS2 9 个 MoveState）

```
BROOD_CALL（召集第一波）
   └→ P1_BRANCH
        ① 已召集 且 无召唤物 → SOLO_STRIKE
        ② 仪式≥3            → REBROOD
        ③ HP<50%            → SHELL
        ④ 否则              → LEGION_CHARGE

LEGION_CHARGE（200% + 全体力量）
   └→ P1_BRANCH

SOLO_STRIKE（160%）
   └→ P3_BRANCH
        ① 仪式≥3     → REBROOD
        ② 召唤物≥2    → BROOD_CALL
        ③ HP<50%     → SHELL
        ④ 否则       → SOLO_STRIKE

REBROOD（处决全部召唤物 + 力量 +2×处决数 + 重召第一波 + 仪式清零）
   └→ P1_BRANCH

SHELL（处决全部召唤物 + 45 格挡 + 仪式清零）
   └→ ELITE_HATCH              // P4 只停留 1 回合

ELITE_HATCH（召唤第二波 + 仪式+1）
   └→ P5_BRANCH
        ① 无召唤物  → FINAL_STRIKE
        ② 仪式≥3    → ELITE_REBROOD
        ③ 否则      → SECOND_WIND_CHARGE

SECOND_WIND_CHARGE（200% + 全体力量 + 仪式+1）
   └→ P5_BRANCH

FINAL_STRIKE（160% + 仪式+1）
   └→ P7_BRANCH
        ① 仪式≥3    → ELITE_REBROOD
        ② 召唤物≥2  → SECOND_WIND_CHARGE
        ③ 否则      → FINAL_STRIKE

ELITE_REBROOD（处决 + 力量 +2×处决数 + 重召第二波 + 仪式清零）
   └→ P5_BRANCH
```

**与原阶段的对应**：

| 原阶段 | STS2 落点 | 说明 |
|---|---|---|
| P1 | `BROOD_CALL` + `LEGION_CHARGE` + `P1_BRANCH` | 召集一次，然后攻击/换防 |
| P2 | `REBROOD` | 原为死内容；改为「3 拍换防」 |
| P3 | `SOLO_STRIKE` + `P3_BRANCH` | 小怪清空后的单体期 |
| P4 | `SHELL` | 只停 1 回合，随后接 P5 |
| P5 | `ELITE_HATCH` + `SECOND_WIND_CHARGE` | 精英波 + 攻击 |
| P6 | `ELITE_REBROOD` | 后半场的 3 拍换防 |
| P7 | `FINAL_STRIKE` + `P7_BRANCH` | 终局攻击循环 |

> 原版的「阶段入口卡 + 阶段行动卡」在 STS2 里合并成一个 `MoveState`：
> `REBROOD` = `pt2_00` + `pt2_10`，`SHELL` = `pt4_00` + `pt4_10`，
> `ELITE_REBROOD` = `pt6_00` + `pt6_10`。因为入口卡本身没有独立演出，
> 分开写只会多出一次空过回合。
>
> `pt5_01` 在原数据里是 `passive0`（可能每回合执行）。STS2 只有 3 个召唤槽，
> 本文按「进入 P5 时执行一次」处理 `ELITE_HATCH`，避免每回合刷满三只精英（§11 Q5）。
>
> 分支条件必须**按上表顺序**写进 `ConditionalBranchState`（先加先判），
> 这是唯一能忠实还原原版「条件 0 优先」的方式（`ConditionalBranchState.cs:44-54`）。

### 4.5 分支条件（伪代码）

```csharp
// P1：先判「小怪清空」，再判「仪式满」，最后判「半血」
p1.AddState(soloStrike, () => SummonedOnce && LivingAdds == 0);

p1.AddState(shell,      () => HpPercent < 0.5);

p3.AddState(broodCall,() => LivingAdds >= 2);

p3.AddState(soloStrike, () => true);

p5.AddState(finalStrike,  () => LivingAdds == 0);
p5.AddState(eliteRebrood, () => BroodAmount >= 3);
p5.AddState(secondWind,   () => true);

p7.AddState(secondWind,   () => LivingAdds >= 2);
p7.AddState(finalStrike,  () => true);
```

`LivingAdds` = `CombatState.GetTeammatesOf(Creature).Count(c => c != Creature && c.IsAlive)`；
`HpPercent` = `Creature.GetHpPercentRemaining()`。

### 4.6 仪式计数与「3 拍换防」

- 定义：Boss 身上挂 `PolemicaBroodPower`，`Amount` 0–3；**除换防/护盾外的每次行动结束 +1**。
- 满 3 后，**下一次**分支进入 `REBROOD` / `ELITE_REBROOD`（不是当拍立即换）。
- 换防与护盾把计数清零（移除 Power）。
- 设计效果：Boss 每 3 次行动换一波召唤物，形成稳定的「召集 → 进攻 → 换防」节奏；
  玩家可以通过「在换防前清光小怪」阻止 Boss 获得换防力量，从而赚取节奏。
- 计数逻辑放在 `Polemica` 内部字段，Power 只做显示与查询，两者同步
  （与上游 `CznActionCountPower` 的做法一致）。

### 4.9 处决 / 换防

- `ExecuteAdds` 对全部存活召唤物**一拍**执行（`Task.WhenAll` 并发触发双方动画，
  不逐个播，否则 3 只召唤物会拖成 9 秒），最后 `CreatureCmd.Kill(adds, force: true)`。
- 召唤物的被处决反应每只自己声明：精锐（岩壳虫/翼壳虫/壳虫）有 `normal_fatal` →
  走 `Fatal` 触发器；兵蚁/盾蚁没有 → 走 `Surprise`（`normal_surprise` 0.533 s）。
- **不要**在 `Kill` 之后再手动 `CombatState.RemoveCreature`：`Kill` 已按原生流程
  移除战斗状态并异步播死亡；提前摘掉会让死亡贴图不消失、悬停刷 `NullReferenceException`。
- 本轮**不使用**全屏三层处决特效（§5.3）；处决呈现 = 首领骨架 `normal_fatal`
  + 召唤物反应动画 + CZN 处决采样 + 原生死亡演出。震屏交给原生的
  `NGame.ScreenShake`（`CreatureCmd` 在伤害结算时已自动触发，不手写位移模拟）。
- 若实机觉得处决不够「重」，可补一次 `ScreenShake(Strong, Normal)` —— 原生
  `CeremonialBeast` / `Vantom` 的相位转换就是这么做的，属可选项。

### 4.10 图鉴设计：专属「CZN 怪物」区块

**问题**：原生图鉴按「章节 → `act.AllEncounters` → `AllPossibleMonsters` →
`ShouldShowInCompendium`」收集条目（`NBestiary.cs:528-570`）。本 mod 首领只走
首领替换（`SetBossEncounter`），从不进章节遭遇池，因此 6 只 CZN 怪在原生流程下
永远收集不到 —— 表现为图鉴里查无此怪。

**候选方案**：

| 方案 | 评价 |
|---|---|
| A. 把 PolemicaBoss 塞进 `act.AllEncounters` | 会改变原版抽卡语义：`_rooms.Boss = rng.NextItem(AllBossEncounters)`（`ActModel.cs:384`）、第二首领随机（`RunManager.cs:763`）都会抽到它，且同一怪会在 3 个章节区块重复出现 |
| B. 顶层注册进 `EventEncounters` | 语义错误：CZN 首领不是事件遭遇，会混进「事件」区块 |
| **C. 图鉴末尾加专属「CZN 怪物」区块（采用）** | 与原生「事件遭遇」区块同构：一个标题分隔条 + 一个条目列表；不影响原生抽卡；区块内 6 只全列、不受首领出现在哪一章影响 |

**设计细节（方案 C）**：

- 在原生 `NBestiary.AddEvents()`（追加「事件遭遇」区块）的位置先插入本 mod 区块，
  保证排序为：第 1 章 → 第 2 章 → 第 3 章 → **CZN 怪物** → 事件。
- 区块标题复用 `NBestiaryLabelDivider`，文本走本地化键
  `bestiary / CZN_MONSTERS.title`，由 mod 的 `localization/{zhs,eng}/bestiary.json`
  提供（`LocManager.GetModdedLocTables` 会把 mod 的同名表合并进原生 bestiary 表）。
- 条目直接以 `BestiaryEntry.FromMonster(monster, PolemicaBoss encounter, RoomType.Boss)`
  添加，心照不宣地复用原生私有 `AddEntries`（排序、未发现置灰、点击连接信号、
  布局创建全部走原实现，行为与原生条目一致）。
- 召唤物的 `ShouldShowInCompendium` 维持 `false`（原生 DecimillipedeSegment 同款口径，
  召唤物不混进章节列表）；专属区块的条目不经该过滤，由补丁直接列举。
- 开关：只在设置「启用 CZN 怪物」开启时展示区块（`MonsterSettings.CznMonstersEnabled`）。
- `EncounterModel.AllPossibleMonsters` 必须包含全部 6 只：除图鉴外，它还被
  预加载 / 资产扫描路径使用。
- 条目的「未发现」锁定态沿用原生规则：玩家**击败过**该怪才会解锁
  （依据存档 `EnemyStats.TotalWins > 0`）—— 被波勒米卡击败不算「发现」。

### 5.0 视觉场景契约

每个 `creature_visuals/*.tscn` 必须包含：

| `IntentPos` | `Marker2D` | `unique_name_in_owner = true` |
| `TalkPos` | `Marker2D` | `unique_name_in_owner = true` |

缩放标定：

- 不要直接使用 `.setting` 的 `scale: 1.3`（那是 CZN 的渲染标定）。
- 先把 `.skel` 导回 JSON 量 `normal_idle` 的骨骼包围盒高度；
  `scale = 目标高度 / 包围盒高度`。Boss 目标高度约 **520–600 px**，召唤物 180–220 px。
- 用 `CZN_AnimLab` 加载 tscn → 勾选动画 → 微调 scale / position，确认
  `Bounds`、`CenterPos`、`IntentPos` 与血条不重叠。

### 5.1 Animator 映射（必须 override）

CZN 的待机动画叫 `normal_idle`，不是 `idle_loop`。若沿用默认 `GenerateAnimator`，
日志会刷 `could not find 'idle_loop'` 且角色不动（上游开发手册 §3.4 同源问题）。

引擎不会发 `"Spawn"` 触发器：`AnimState` 只认 `Hit` / `Dead` / `Attack` / `Cast` /
`PowerUp` 等内置触发器，登场动画必须做成 `CreatureAnimator` 的**初始状态**
（原生 Parafright / GasBomb 同做法，见 `Parafright.cs` / `GasBomb.cs`）。

各怪的实际映射（`GenerateAnimator` 实现，括号内为 `TriggerAnim` 的等待秒数）：

| 怪物 | 初始状态 | `Hit`（眩晕时） | `Hit` | `Dead` | 其它触发器 |
|---|---|---|---|---|---|
| 波勒米卡 1001013 | `normal_enter` | `normal_groggy` | `normal_hit` | `normal_death` | `AttackHeavy`→`normal_skill1_3`(1.70)、`AttackFast`→`normal_skill4`(1.03)、`Summon`→`normal_skill2_3`(2.43)、`Shell`→`normal_skill3`(2.60)、`Fatal`→`normal_fatal`(1.5) |
| 军团兵蚁 1001009 | `normal_summon` | `normal_groggy` | `normal_hit` | `normal_death` | `RallyAttack`→`normal_skill1`(1.13)、`HarassAttack`→`normal_skill2`(1.03)、`Surprise`→`normal_surprise`(0.55) |
| 军团盾蚁 1001010 | `normal_summon` | `normal_groggy` | `normal_hit` | `normal_death` | `Attack`→`normal_skill1`(1.13)、`Cover`→`normal_skill2`(1.03)、`Surprise`→`normal_surprise`(0.55) |
| 岩壳虫 1001019 | `normal_enter` | `normal_groggy` | `normal_hit` | `normal_death` | `Crush`/`Guard`→`normal_skill1`(1.50)、`Harden`→`normal_skill2`(0.90)、`Fatal`→`normal_fatal`(1.5) |
| 翼壳虫 1001018 | `normal_enter` | `normal_groggy` | `normal_hit` | `normal_death` | `Attack`/`Guard`→`normal_skill1`/`normal_skill2`(1.50)、`Fatal`→`normal_fatal`(1.5) |
| 壳虫 1001004 | `normal_enter` | `normal_groggy` | `normal_hit` | `normal_death` | `Attack`/`Guard`→`normal_skill1`/`normal_skill2`(1.50)、`Fatal`→`normal_fatal`(1.5) |

四条通用规则：

- 非循环动画统一 `NextState = idle`；`normal_death` 不设 NextState。
- **眩晕**：引擎没有 stun 触发器，用 `AnimState` 的条件分支实现 ——
  先 `AddAnyState("Hit", normal_groggy, () => Creature.IsStunned)`，
  再 `AddAnyState("Hit", normal_hit)`。`AnimState` 按**插入顺序**取第一个条件成立的分支，
  所以带条件的那条必须先加（`Creature.IsStunned` == `Monster.NextMove.Id == "STUNNED"`）。
- **初始化**：`CreatureAnimator(initialState, controller)` 构造时就会 `SetNextState`，
  所以登场动画会在进房时真正播一遍。
- **一只怪有多套攻击动画时不要共用 `Attack` 触发器**：兵蚁的「战吼突刺」用
  `RallyAttack → normal_skill1`，「撕咬」用 `HarassAttack → normal_skill2`；
  盾蚁用 `Attack`/`Cover`；精英用 `Crush`/`Guard`/`Harden`。
  岩壳虫的 `Crush` 与 `Guard` 两种攻击都落在 `normal_skill1`（素材里也只有这一段
  攻击动画），不额外拆分触发器。

音效**不**依赖 `TriggerAnim`：它只对 `Attack` / `Cast` / `PowerUp` 自动找音效，
自定义触发器一律靠显式 `CznMonsterSfx.Play(...)` 或 `WithAttackerFx(...)`。

### 5.2 音效设计

**占位路径 + 前缀补丁 + 本地 ogg**：28 条 CZN 采样导出到
`res://CznMonster/audio/sfx/polemica/<怪物 id>/*.ogg`。

| 环节 | 设计 |
|---|---|
| 占位路径 | `AttackSfx` / `DeathSfx` / `HurtSfx` 返回 `event:/sfx/enemy/enemy_attacks/cznmonster/<ENTRY>/<clip>`（`CznMonsterSfx.Placeholder`） |
| 拦截 | `SfxCmd.Play(string,float)` 前缀补丁：命中前缀就播本地 ogg 并吞掉原调用 |

| 零侵入 | 补丁只识别本前缀，其余路径原样 `return true` 走原实现（铁律 6），先判 `instance is <本角色>` |

怪物 entry → clip 映射（clip 名对齐动画 / 动作语义）：

采样缺失时的约定（避免「静音 = bug」的误判）：

- **兵蚁 / 盾蚁没有 `summon` 采样**，登场复用其 `enter` 采样（动画仍用 `normal_summon`）。
- **兵蚁 / 盾蚁没有 `fatal` 采样**，被处决时不额外发声（`ExecuteSfxClip => null`），
  只靠骨架 `normal_surprise` 演出。
- **兵蚁 / 盾蚁也没有 `death` 采样**，死亡复用 `skill2`。
- **三只精英有 `fatal` 采样但没有独立死亡采样**：处决时已播 `fatal`，
  所以死亡不发声（`DeathSfxClip => null`、`HasDeathSfx => false`），避免响两声。

`DamageSfxType => DamageSfxType.Armor`（甲壳）保持不变 —— 受击的闷响由它决定，
和上面这些「语义采样」不冲突。

### 5.3 处决 / 换防特效：本轮不使用

**素材语义**：`effect/1001013_fatal_eff_{b,f,sub}` 三层的原始用途是
**首领杀死玩家时的处决演出**（配套 `camera_path` 运镜与 `node` 节点时序，
挂载对象是玩家）。本设计把它挪用为「处决自家召唤物」的全屏演出后，
语义与观感都不对位（换防是自家仪式，不是击杀玩家），因此**先整个移出，
本轮不接回**。

- 本轮处决呈现 = 首领骨架 `normal_fatal` + 召唤物反应 `normal_surprise`/`normal_fatal`
  + 处决采样 + `CreatureCmd.Kill` 原生死亡演出（§4.9）。
- 特效三层只作（将来可能接回的）时序参考：背景层 −600 → 角色之下、前景 3 / 副 5 →
  角色之上，`z_index` 只在同一父节点内排序，接回时背景层必须挂
  `BackCombatVfxContainer`，前景两层挂 `CombatVfxContainer`。
- 接回前提：素材语义重新裁决（例如改成「Boss 击杀玩家时的死亡演出」），届时
  挂载点应是玩家而不是换防流程。

### 5.4 静态头像 / 动画立绘：评估结论（**不实现**）

**素材**（`face/` 下：12 张静态 PNG + 3 套动画立绘骨架）：

| 位置 | 内容 | 用途 |
|---|---|---|
| `face/mob/portrait_boss_1001013.png` | Boss 全身立绘 | 事件对话 / 战果大图 |
| `face/mob/portrait_boss_crop_10010xx.png` | 裁剪图 5 张 | 头像框、提示条 |
| `face/mob/face/face_mob_10010xx.png` | 小头像 6 张 | Tooltip、血条旁、图鉴列表 |
| `face/portrait/{1001004,1001009,1001010}.{json,atlas,png}` | **动画立绘 3 套**（Spine） | 活动界面、抽卡/养成页 |

**为什么不做：**

1. **图鉴不缺这张脸。** 图鉴选中怪物后实例化的是 `NCreature`，
   加载的是 `VisualsPath` 指向的**战斗 Spine**；6 套战斗骨架本来就能动，
   静态头像在这个界面里没有挂载点（§4.10 的专属区块同样走战斗 Spine）。
2. **战果页 / 地图 / 血条已经解决。** 「跑图历史图标 + 轮廓」和地图图标是
   STS2 真正会读的怪物「脸」，静态 `face_mob_*` 与它们功能重叠。
3. **单怪 Mod 没有「立绘面板」。** 动画立绘原本用于 CZN 的角色/怪物详情页；
   STS2 没有等价面板，要显示只能自己注入 UI 节点，且 3 套立绘只覆盖 3 只召唤物。
4. **成本与收益不成比例。** 3 套立绘要再走一遍 4.2.11 转换 + 写一套自定义面板
   （布局、缩放、输入遮挡、多语言、分辨率适配），换到的只是一个原版 UI 不展示的页面。

## 10. 风险与边界

| 风险 | 说明 | 缓解 |
|---|---|---|
| 力量雪球 | 3 只小怪每回合可能给全体 +3~+4 力量；换防还会把未清召唤物转化为 Boss 力量 | 玩家可优先清小怪；岩壳虫 +4 视实测下调 |

## 11. 疑问与裁决

> 以下每条都是「疑问 + 裁决」；未推翻前按裁决值实现，改动只影响数值表或一张映射表，不动结构。

### Q1 5 只召唤物的中文名缺失

用「军团兵蚁 / 军团盾蚁 / 岩壳虫 / 翼壳虫 / 壳虫」，
在 `localization/{lang}/monsters.json` 里集中管理；拿到官方名后只改 JSON，不动代码。

### Q2 `cs00_0002 / 0003 / 0007` 的真实语义

三者只有 `link_cs_id`，包内没有名称/图标/描述。按「三只精英各给一种经典减益」
的最稳映射：`1001004→虚弱(Weak)`、`1001019→脆弱(Frail)`、`1001018→易伤(Vulnerable)`，
兵蚁的 `cs00_0007` 沿用易伤。若后续拿到官方文本，只需改 §4.7 的 3 个 `PowerCmd.Apply` 泛型。

### Q3 护盾 `SHIELD_ATTR_AUTO` 是否跨回合

无法确认。v1 用普通格挡 45（P4 只停留 1 回合，语义足够接近）；
若确认原版护盾跨回合，改为 `PlatingPower`（每回合自动补）或 `BarricadePower`（不清格挡）。
精英的 `cs02_0091` v1 不实现；若精英太脆，再补 5 格挡或 5 层 `PlatingPower`。

### Q4 「处决其他怪」的目标到底是哪边

「Boss 的敌人 = 玩家」会得出秒杀玩家，不成立；按「除自己以外的己方」理解才是换防。
采用「按说话者阵营的全体」语义：伤害指向玩家，增益/护盾/处决指向己方（§2.6）。
若后续发现原版其实是「献祭一只小怪回血」，只需在 `ExecuteAdds` 后补一个 `CreatureCmd.Heal`。

### Q5 P2 / P6 在原数据中不可达，是否要补全

把「仪式」改成**每次 Boss 行动 +1、满 3 换防**（本文采用，§4.6）。
P2/P6 变成每 3 拍一次的换防循环，既保留「三拍召集」的意图，又有节奏。
若要 100% 忠实原数据，则删掉 `REBROOD/ELITE_REBROOD` 与仪式 Power，
但后半场会退化成「P5 召一次精英 → P7 打到死」，内容明显变少。

### Q6 CZN 语音 bank 怎么处理

`tools/extract_fmod_bank.py` 提取，**不重建 bank** ——
6 个 bank 共 28 条采样直接导成 ogg，由 `CznMonsterSfx` + `SfxCmd` 前缀补丁播放（§5.2）。

### Q7 处决特效 / 运镜是否要做

**裁决（v2.0 更新）：本轮不做。** 三层特效的原始语义是「首领杀死玩家时挂在玩家身上」，
挪到换防流程上语义与观感都不对位，已整个移出（§5.3）。
将来若接回：只做特效、不做运镜；`camera_path/*.json` 与 `node/*.json` 只当时序参考，
背景层挂 `BackCombatVfxContainer`、前景两层挂 `CombatVfxContainer`,
震屏交给原生 `NGame.ScreenShake`；且需重新裁决挂载语义（例如改为玩家死亡演出）。

### Q8 Boss HP 是否要按原比例 1:1

采用 450（升华 475）。RANK_S 的压迫感靠「召唤 + 力量雪球 + 换防」体现，
不靠血牛；若实测偏短，优先加召唤物 HP/攻击，而不是加 Boss HP。

### Q9 `1001009` 的 `stance1` 姿态要不要实现

v1 不实现姿态切换，只使用 `normal_*`。
如果后续要加「兵蚁半血变姿态1」，在 `PolemicaLegionSoldier` 里 override
`GenerateAnimator`，用 `HasPower`/`HpPercent` 选动画即可。

### Q10 岩壳虫 +4 力量是否过强

原始 `cs00_0001 +4` 是真实数据，但配合 Boss 的全体 +1，后期单次 18 伤害可能涨到 30+。）
先按 +4 实现并实测 T6/T7；若第 3 章玩家在精英波减员明显，改为 +3，
并在 §8.2 表里同步。不要直接砍半，否则「岩壳硬化」这个招牌动作会失去威胁。

### Q11 岩壳虫「弃光手牌」是否过强

`1001019_01_pt1_11` 只能推断为「把玩家手牌全部弃掉」；三只精英同时在场会空过。
v1 保留「弃光手牌」但只由岩壳虫出现 + 硬冷却（3 回合内不再使用）；
实测若仍然过强，改为「随机弃 2 张」。改法只动 `RockHardenMove` 的
`CardCmd.Discard` 参数与分支冷却，不动其它结构。

### Q12 召唤物基础伤害是否过高（已裁决）

确实过强：第一波同回合总输出 33 > Boss 单发 22，且兵蚁 Rally 力量滚雪球无约束。
平衡调整将 100% 档 15 → 12（升华 13）、150% 档 22 → 18（升华 20），
落点见 §3.1 实装表；换防 / 掩护 / 防御拍的 6 / 9 档与 Boss 的 30 / 24 档不动。
第 1 / 2 章由章节系数继续缩放（12 × 3/4 = 9，18 × 3/4 = 13）。
若实测仍偏强，下一档优先砍「兵蚁 Rally 连用上限 2 → 1」而不是再降伤害：
伤害下调影响所有回合，连用上限只削滚雪球的斜率。

### Q13 波勒米卡在图鉴不会出现（已裁决）

原生图鉴流程收不到本 mod 首领（原因见 §4.10）。扰乱原生遭遇池的方案不可取，
采用图鉴末尾专属「CZN 怪物」区块：标题分隔条 + 6 个条目，
复用原生 `AddEntries`，开关跟随「启用 CZN 怪物」设置。
