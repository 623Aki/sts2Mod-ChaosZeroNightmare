## 1. 机制设计

### 1.1 塞拉菲翁状态机（7 个 MoveState + 2 个分支）

```
SOVEREIGN_UPRISING（登场态，HiddenIntent；只等登场动画收尾 1.2–1.6s）
   └→ P1_BRANCH（条件分支，先加先判）
        ① _revivePending      → REVIVAL（复归拍）
        ② LivingAdds==0       → FINALE_OPEN（终局起手）
        ③ _p1Turn >= 2        → FINALE_CYCLONE（三拍循环第 3 拍）
        ④ 否则                → SOVEREIGN_BITE（双牙）

REVIVAL（复归拍）
   同回合排入守卫：颂歌当拍（同 RoundNumber）被 SetMoveImmediate 排入时本拍退化为占位空拍
   （不清 revivePending；意图保持 REVIVAL 显示），复归内容留到自己下一拍。
   正式执行：①ToShieldForm 切持盾（1.0s）→ ②附盾 45 → ③回稳三连 3×12
   └→ P1_BRANCH（_p1Turn 归 0；_p2Form=true）

FINALE_OPEN（光耀增幅：力量 +2，FinaleBuff 1.5s）
   └→ FINALE_LOOP（终焉四连 4×12，每拍循环，无出口——真死即终）

FADING（濒死占位空拍，HiddenIntent）
   └→ FADING_BRANCH（先加先判）
        ① _revivePending → REVIVAL
        ② 否则 → 留在 FADING
```

要点：

- **复归入边只用 `_revivePending`**。引擎在**玩家回合开始**掷敌方下一拍（`CombatManager.cs:743 PrepareForNextTurn`），而敌方格挡到**敌方回合开始**才清零（`Creature.cs:696 AfterTurnStart → ClearBlock`）——RollMove 时上一拍的盾还在，若把 `Block > 0` 当入边复归拍会无限自循环。
- **同回合排入守卫**（`_revivalQueuedRound`，记录 `ICombatState.RoundNumber`，敌方回合结束才递增）：阿克鲁斯（add1）先手，颂歌拍里 `SetMoveImmediate(REVIVAL)` 强改的 NextMove 会在同一敌方回合内被塞拉菲翁的 PerformMove 立即执行——同回合执行时本拍只占位，**起身只赋予意图，复归内容下一拍再执行**；下一掷经 P1/FADING 分支首谓词重新选中 REVIVAL。
- **P3 终局无出口**：仅当阿克鲁斯死亡且塞拉菲翁健康时进入，此后 `finaleLoop → finaleLoop` 自环到底；濒死的塞拉菲翁不会走到终局——伴生死亡的 `AfterDeath` 钩子对它直接 force kill（§1.5）。
- **敌方行动顺序**：按槽位名排序 `add1 < "boss"`，阿克鲁斯先于塞拉菲翁行动（同回合排入守卫的动机所在）。

### 1.3 阿克鲁斯状态机（5 个 MoveState + 1 个分支）

```
GUARD_BRANCH（守护分支，开场即此；先加先判）
   ① SeraphionHalfState.IsHalfDeath → RESCUE_STRIKE（切救援）
   ② _guardTurn % 2 == 0            → GUARD_WARD
   ③ 否则                           → GUARD_ASSAULT

RESCUE_CYCLE（救援三拍严格串行，不回分支）
   RESCUE_STRIKE → RESCUE_CURSE → RESCUE_SONG ─→ GUARD_BRANCH
       （颂歌拉起塞拉菲翁 → IsHalfDeath 归 false → 下掷回守护；守护拍先播 ToGuard 前缀）

GUARD_CYCLE（守护二拍严格串行，不回分支）
   GUARD_WARD ⇄ GUARD_ASSAULT → GUARD_BRANCH
```

- `IsHalfDeath` 读的是 `Seraphion.FadingActive`（濒死演出状态），**不是**濒死 Power 在场——那张 Power 是开场挂载、可整场保留的被动，不能当濒死信号。
- **救援不滞后一拍**：塞拉菲翁进濒死的当场（`EnterFading`）经 `SeraphionHalfState.NotifyArkrusRescue` 调 `Arkrus.ForceRescueMove()` → `SetMoveImmediate(RESCUE_STRIKE, force)` 消除已掷好的守护拍。引证时序：引擎只在玩家回合开始 RollMove，濒死发生在玩家回合中间，不即时改写则本拍沿用旧意图。
- 伴生死亡不在 `Arkrus` 类内实现（游戏侧无 `MonsterModel.OnAfterDeath` 钩子），由 Power 的 `AfterDeath` 监听（§1.4）。

### 1.5 濒死体制（`SeraphionHalfDeathPower`，全部钩子）

Power：Type `Buff` / `StackType.Counter`（不被 Artifact 挡）/ `ShouldPlayVfx=false` / `ShouldScaleInMultiplayer=false`。开场由 `Seraphion.AfterAddedToRoom` 在有阿克鲁斯在场时挂载。

| 钩子 | 行为 |
| --- | --- |
| `ShouldDie(creature)` | `true` 当且仅当 `creature != Owner`——**Owner（塞拉菲翁）不死**，其它生物零侵入（照常走原判）。 |
| `AfterPreventingDeath(creature)` | 濒死入场（幂等，FadingActive 时直接返回）：`Heal(1)` → 震屏（Medium/Short）→ `EnterFading()`（置 FADING 意图 + 通知阿克鲁斯救援）→ 当场播 `EnterDying`（`stance3_death` 2.37s → 收进 `stance3_idle` 跪姿循环）→ 逐个卸掉塞拉菲翁身上全部其它 Power（正规卸载走 `AfterRemoved`），**濒死不灭本体保留**；格挡不动。 |
| `ModifyHpLostAfterOsty` | `Owner` 且 `FadingActive` 时生命流失归 0（垂死免疫；伤害演出照常）。**只在濒死后生效**——战斗开始到濒死之间必须可被正常打到 0，否则死亡拦截永远不触发。 |
| `ShouldAllowTargeting(target)` | 濒死中不可被任何卡牌指定目标；颂歌治疗后恢复可指定。 |
| `ShouldAllowHitting(creature)` | 濒死中整体排除出受击列表（覆盖 AoE/全体效果）。伴生死亡的 `Kill(force:true)` 走死亡管线不经这两个钩子，不受影响。 |
| `AfterDeath(...)` | 监听到 **阿克鲁斯死亡**：Owner 濒死 → `CreatureCmd.Kill(force:true)` 真死（播 `stance3_death`）；Owner 健康 → 卸掉濒死不灭 Power（**Power 唯一卸载点**），战斗继续。 |

**濒死保护可循环**：救援颂歌路径不卸 Power；第二次濒死照常被拦截（对齐 CZN 原数据 P4 可反复进入）。

### 1.6 救援与复归时序（全链路）

```
塞拉菲翁受致命伤（阿克鲁斯存活）
  → Power.ShouldDie 拦截 → AfterPreventingDeath：
      Heal(1) → 震屏 → EnterFading（意图=FADING + NotifyArkrusRescue）
      → 播 EnterDying（stance3_death 2.37s → stance3_idle 跪姿）→ 清其它 Power
  → 阿克鲁斯 ForceRescueMove：下一拍当场改写为 RESCUE_STRIKE（意图立即变化）
  → 救援三拍：突刺(12+自盾45) → 咒缚(虚弱2/脆弱2/力−1) → 颂歌

颂歌（BeginRevivalAsync）
  → Heal(round(MaxHp×0.5))    // 195 上限即 98；升华 103
  → ExitFading()（免疫停止；对齐原数据「cur_hp≥1」时点；可再受击/可指定目标）
  → 当场播起身：Revival = stance3_to_normal（1.0s）+ revival 采样（跪姿 → 站立）
  → RequestRevival：置 _revivePending + 记 _revivalQueuedRound
      + SetMoveImmediate(REVIVAL)（Attack+Defend 意图当场显示）

塞拉菲翁自己的下一拍（REVIVAL_MOVE）
  同回合排入守卫 → 若颂歌同回合（RoundNumber 相同）→ 占位空拍，留到再下一拍
  正式执行：ToShieldForm 切持盾（1.0s）→ 附盾 45 → 回稳三连 3×12
  → 回 P1_BRANCH；持盾形态标志 _p2Form=true，下个攻击/增幅拍先播 ToNormal 前缀
```

颂歌歌毕阿克鲁斯立即回守护定式（`_rescue=false`，下次行动播 `ToGuard` 前缀）；一次救援链里塞拉菲翁只能被拉起一次（颂歌判定 `IsHalfDeath`，已在起身时就为 false）。

### 3.3 Animator 映射（`GenerateAnimator` 实表）

引擎只认 `Hit` / `Dead` 内置触发器（无 "Spawn"，登场动画 = 初始 AnimState；CZN 待机叫 `normal_idle` 必须自带）。

**塞拉菲翁**：初始 `normal_enter`→`normal_idle`(loop)。
AnyState 触发器：`Bite`→normal_attack_play1、`Cyclone`→normal_attack_play2、`Revival`→stance3_to_normal、`ToShieldForm`→normal_to_stance1、`ShieldStance`→stance1_attack_play1、`ToNormal`→stance1_to_normal、`FinaleBuff`→stance2_buff_1、`FinalQuad`→stance2_attack_play1、`ToHalfDeath`→normal_to_stance3、`EnterDying`→stance3_death(2.37s)→NextState stance3_idle。
条件分支（先条件后默认）：`Dead` = `HalfDeathActive ? stance3_death(终态) : normal_death`；`Hit` = `Creature.IsStunned ? normal_groggy : normal_hit`。
（`EnterDying` 与真死 `Dead`→`stance3_death` 分开注册：前者有 NextState 收进跪姿，后者是终态。）

**阿克鲁斯**：初始 `normal_enter`→`normal_idle`(loop)。
AnyState：`GuardWard`→normal_buff_1、`Assault`→normal_attack_play1、`ToRescue`→normal_to_stance1、`RescueStrike`→stance1_m_attack_01、`RescueCurse`→stance1_debuff_1、`RescueSong`→stance1_unique_1、`ToGuard`→stance1_to_normal。
条件分支：`Dead` = `_rescue ? stance1_death : normal_death`；`Hit` 同上（groggy 优先）。

### 3.4 音效（`CznMonsterSfx` 占位路径机制）

两个 CZN bank（24 + 12 = 36 条采样）已全部导出为 ogg 到 `res://CznMonster/audio/sfx/diallos/{1003017,1003016}/`。`MonsterModel.AttackSfx/DeathSfx/HurtSfx` 返回占位事件路径（前缀 `event:/sfx/enemy/enemy_attacks/cznmonster/<entry>/<clip>`），由 `Registration.CznMonsterSfxPatch` 的 `SfxCmd.Play`/`PlayDeath` 前缀补丁解析成本地 ogg 并吞掉原调用（其它怪物零影响）。战斗开始时按遭遇预热缓存；播放器挂 `NCombatRoom` 离房即失效。

clip → 采样实表（本组相关）：

| entry | clip → ogg | 触发点 |
| --- | --- | --- |
| SERAPHION | `enter`→se_seraphion_normal_enter；`bite`→normal_attack_play1；`cyclone`→normal_attack_play2；`finalebuff`→stance2_buff_1；`finalquad`→stance2_attack_play1；`revival`→stance3_to_normal（颂歌当场起身）；`toshield`→normal_to_stance1；`shieldstance`→stance1_attack_play1；`tonormal`→stance1_to_normal；`hurt`→normal_hit；`death`→normal_death；`death_fading`→stance3_death；`fatal`→normal_fatal（占位保留未使用） | DeathSfx 按 `_fading` 走 `death_fading`/`death`；`revival` 在颂歌治疗当场播 |
| ARKRUS | `enter`→normal_enter；`ward`→normal_buff_1；`assault`→normal_attack_play1；`torescue`→normal_to_stance1；`rescuestrike`→stance1_m_attack_01；`rescuecurse`→stance1_debuff_1；`rescuesong`→stance1_unique_1；`toguard`→stance1_to_normal；`death`→normal_death；`death_rescue`→stance1_death；`fatal`→normal_fatal（占位保留未使用） | DeathSfx 按 `_rescue` 走 `death_rescue`/`death` |

静音约定：bank 无 `normal_to_stance3` 采样 ⇒ 濒死入场只播动画（EnterDying）；阿克鲁斯无受击采样 ⇒ 不发声。其余导出采样（stance1_* 等备用段）未挂表。

## 6. 注册与补丁

| 挂点 | 内容 |
| --- | --- |
| `MonsterContent.BossEncounters` | `PolemicaBoss` + `SeraphionEncounter`。首领永不进普通池，只走首领替换 |
| `BossPlacementPatch`（`RunManager.GenerateRooms` postfix + 两个 SetUp 前缀捕获 RunState） | 按设置替换各章首领：「指定模式」= 在所选章节放一个未用的 CZN 首领（未用首领中随机）；「随机模式」= 每只未用 CZN 首领随机占用一个未被 CZN 占用的章节，不足时保留原生首领；`UsedBossIds` 同局去重（读档按已挂首领重建）；放置时写 `SeraphionScaling.ActIndex` |
| `MonsterPoolPatch` | 非首领清单（`NonBossEncounters` 当前为空，补丁对空清单安全） |
| 图鉴 |「CZN 怪物」区块按 `BossEncounters` 遍历注入；条目来源 = `SeraphionEncounter.AllPossibleMonsters`（2 条）；招式列表排除 UPRISING/FADING |
| `CznMonsterSfxPatch` | `SfxCmd.Play`/`PlayDeath` 前缀接管（占位路径 → 本地 ogg），其余路径原样返回 |
| `SettingsInjectPatch` | 设置项：`CznMonstersEnabled`、`BossPosSpecified` + `BossChapter`、`BossPosRandom`、`CustomBossHp`（只作用于主敌血量） |
| `ActionCountPatches` / `ActionCountRuntime` | 行动计数基础（`CznActionCountPower` 复用条目） |

补丁纪律沿用全局铁律：全部 Harmony 补丁限定本 mod 命名空间、先判本 mod 类型再动原实现，其余 `return true` 零侵入；`HarmonyPatchAll` 未使用。
