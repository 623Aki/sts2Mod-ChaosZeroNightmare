## 0. 三层数据链

```text
30093.srcs               ─ command_sets / loop_groups   技能由哪几条 command 拼成
      ↓
30093.srmd               ─ command.<cmd>   主体：战斗全动作（48 条）
30093_battle_ready.brmd  ─ command.<cmd>   出牌特写（4 条）
30093_01.srmd            ─ command.<cmd>   变体补充（move / stop）
              ├ ani[]        身体骨架相位（clip + 时长）
              ├ effect[]     特效组挂载（file_name = 组名）
              └ hit / damage / shake / cam_* / color_blend / bg_blend / …
      ↓
<组名>.cfx               ─ primitive[]    组展开成逐层 {source, z, x, y, …}
```

读法要点：

- `effect[].file_name` 是**组名**（= `effect/<组名>.cfx`），骨架名在 `.cfx` 的 `primitive[].source`。
- `.cfx` 的 `z` 为空串或 key 缺失 ⇒ 真值 **0**。
- `delay` / `duration` 单位一律**毫秒**。
- 事件靠 `guid` / `from_guid` 串成播放树，`sequence` 决定兄弟顺序。
- **三份模型文件都读**：`ug_attack` 在 `.srmd`（全屏演出）与 `.brmd`（出牌特写）里重名不同义。

## 7. 特效组库（五类桶）

上面 §0–§6 是**编排视角**（技能 → command → 组）；本节是**组视角**（组 → 逐层明细），两节共用同一份 `_battle_mapping_30093.json`。

组键就是 `effect/<组名>.cfx` 的文件名 —— **无歧义由源保证**：
同一个骨架在不同招式下 clip 不同（如 `eff_sword_target` 在普通攻击下播 `attack_play1_target`、在 u5 下播 `u5_attack_play1_target`），
而源把「招式 × 挂载侧」各自写成一个 `.cfx`，clip 已写死在文件里。

`drv` 列：`源` = 由 `.srmd` / `.brmd` 的 command 驱动；`推断` = 找不到驱动文件，按名字族归桶（**引用前需先确认触发时机**）。
