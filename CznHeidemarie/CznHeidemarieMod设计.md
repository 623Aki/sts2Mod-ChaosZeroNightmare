# CznHeidemarie 增加 mod 设计

## 角色设定

| 项目   | 内容      |
| ---- | ------- |
| 名称   | 海德玛丽    |
| 种族   | 人类      |
| 生日   | 2月4日    |
| 异能   | 凝铸极光    |
| 所属势力 | 希安联邦乐园号 |

### 背景

园号的市长，大众心中的英雄。多年前的一场战斗让她被乐园号的市民铭记，却也在她的心底留下了不为人知的隐痛。自一线退下之后，她一如往昔般守护着乐园号的市民。只是那明朗的笑容之下，藏着未曾愈合的旧伤。

## 卡牌设计表

> **公共说明**：
> `代码映射` 列只写文件名，统一位于
> `Characters\Heidemarie\Cards\` 下（工程根 `CznHeidemarie\`）。
> 例：`HeidemarieStrike.cs` → `CznHeidemarie\Characters\Heidemarie\Cards\HeidemarieStrike.cs`；
> 本地化 key 为 `res://CznHeidemarie/localization/zhs/cards.json` 中的 `HEIDEMARIE_<卡名大写>`。
>
> `卡面映射` 列只写文件名，统一位于 `images\packed\card_portraits\heidemarie\` 下，
> 文件名为 `heidemarie_<slug>.png`，slug 由 C# 类名经 `StringHelper.Slugify`
> 派生（如 `HeidemarieSwordlight` → `heidemarie_swordlight`）。
> 打包后运行时路径为 `res://images/packed/card_portraits/heidemarie/heidemarie_<slug>.png`，
> 由卡牌基类 `HeidemarieCard.PortraitPath` 拼出；文件缺失时自动回退战士占位图。
>
> **稀有度取值**：`Basic` 只能来自初始卡组（奖励 / 商店 / 战斗随机生成都不出）；
> `Common` 可正常获取；`Token` 为衍生牌（不参与奖励 / 商店抽取）。
>
> **效果说明**：文本中描述为`造成{Damage:diff()}点伤害`即代表为指向性伤害牌，
> `对随机敌人造成{Damage:diff()}点伤害`则代表为随机性伤害牌。
> `对全体敌人造成{Damage:diff()}点伤害`则代表为范围性伤害牌。

## 实现说明（2026-10-13 回写）

### 伤害公式

```
最终伤害 = (原基础伤害 + 固定伤害增加) × (1 + Σ百分比增伤)
```

### 增伤口径（2026-10-22：两个增伤区合并为一个出口）

```
最终伤害 = (原基础伤害 + 固定伤害增加) × (1 + (一次性注入 + 极光连锁基线 + (极光剑 ? 极夜 : 0)) / 100)
```

- 引擎乘算区是连乘（`Hook.ModifyDamageInternal`：`num *= num3`），因此全角色**只保留
  `Powers/HeidemarieDamagePercentPower.cs` 一个 modifier**；原先独立的「极光剑增伤区」
  标记能力（`HeidemarieAuroraDamagePoolPower`）降级为来源汇总器，不再自己提供因子。
- 极光剑专属部分（仅极夜）只在 `cardSource is HeidemarieAuroraSword` 时计入；
  一次性注入（绝响每剑 +100% / 解放极光每消耗一剑 / 一缕光芒每张连接牌）与
  极光连锁基线（层数 × 5）对所有强化攻击生效。
- 「极夜」按张数计费：有层数时固定 +100%，每张剑结算后 -1 层（层数不会叠加在同一张剑上）。

### 2026-10-24 DARV「尘封魔典」空引用（**A 阶段已落地，B 阶段待做**）

**现象**：多人局每次进 DARV 先古事件，日志刷
`NullReferenceException at DustyTome.SetupForPlayer_Patch2`，且**海德玛丽这一页事件选项为空**。
与队友选了什么无关（异常发生在「生成选项」阶段）。

**根因链**（完整推导见当次会话记录）：

1. `Darv.GenerateInitialOptions()` 有 50% 概率把「尘封魔典」加进选项，加之前会先调
   `dustyTome.SetupForPlayer(Owner)`；
2. 原版 `DustyTome.SetupForPlayer` 的候选集 = 卡池里 `CardRarity.Ancient` **且不在**
   `ArchaicTooth.TranscendenceCards` 里的牌，然后 `AncientCard = NextItem(items).Id`；
   候选为空时 `NextItem` 返回 null ⇒ 取 `.Id` 空引用；
3. 海德玛丽卡池里**唯一**的先古牌是「终焉」，而它经
   `Registration/HeidemarieAncientTranscendencePatch.cs` 注册进了
   `ArchaicTooth.TranscendenceUpgrades`（= `TranscendenceCards` 的来源）⇒ 候选恒为空；
4. `TranscendenceCards` 在整个游戏里**只有 `DustyTome.SetupForPlayer` 一处使用**（它就是「魔典黑名单」）。

**A 阶段（已实现，`Registration/HeidemarieDustyTomePatch.cs`）**

| 补丁 | 作用 |
|---|---|
| `HeidemarieDarvDustyTomeOptionPatch`（Postfix `Darv.GenerateInitialOptions`） | 本角色无可用先古牌时，按 `EventOption.Relic is DustyTome` 摘掉魔典选项（否则选项文案里 `{AncientCard.StringValue}` 无值，真选中时 `AfterObtained` 还会炸） |
| `HeidemarieDustyTomeSetupGuardPatch`（Prefix `DustyTome.SetupForPlayer`） | 兜底：同判定成立时跳过原方法，消掉 `NextItem(空).Id` 的空引用 |

判定统一走 `HeidemarieAncientCardAvailability.HasEligibleAncientCard(player)`，
只对 `Heidemarie` 生效（其它角色一律放行，零侵入）。
**代价**：该角色遇到 DARV 时只有 2 个选项，且永远拿不到尘封魔典。

**B 阶段（后期）**：给卡池补一张**不在 `TranscendenceUpgrades` 里**的 `Ancient` 牌
（新卡或启用现有先古牌），魔典即恢复正常并送出那张牌，「终焉」仍**只**由太古之牙淬炼获得。
A 的两个补丁与 B 共用同一判定，届时会**自动不再介入**，无需回滚代码。

**明确不采用**：把「终焉」从 `TranscendenceCards` 摘掉 —— 那样候选集会变成 `[终焉]`，
尘封魔典就能直接送「终焉」，破坏其独占性（NRE 会消失，但设定被打破）。

**验证**：`dotnet build` 0 error；进 DARV 不再出现该 NRE，日志改为一条
`DARV：本角色卡池无可用的先古牌…已摘除「尘封魔典」选项`。
