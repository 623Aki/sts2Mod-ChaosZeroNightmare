## 一、STS2 的战斗风格与特色（源码调研结论 · 跨轮通用）

调研对象：`SlayTheSpire2_source/`（反编译源码，权威于一切教程）。

### 1.1 骨架仍是尖塔，但节奏更快

| 项目    | STS2 实际情况                      | 源码依据                                                                |
| ----- | ------------------------------ | ------------------------------------------------------------------- |
| 每回合能量 | **3**（调试角色除外）                  | `CharacterModel.MaxEnergy => 3`                                     |
| 第二资源  | **星能 Stars**：能量不足时 1 能量 = 2 星  | `PlayerCombatState.Stars`；`Hook.ShouldPayExcessEnergyCostWithStars` |
| 格挡清空  | 回合结束清空，但**第 1 回合不清空**（STS2 新增） | `Creature.cs:690-694`，`TurnNumber == 1` 跳过 `ClearBlock()`           |
| 出牌上限  | 无 STS1 的"每回合限制"，靠能量自然限制        | —                                                                   |

> **设计含义**：STS2 允许玩家在一回合内滚更大的雪球（星能补费、首回合保格挡），
> 因此"单卡高上限 + 需要 setup"的设计比 STS1 更安全 —— 这正好契合本角色
> 「攒连接 → 一波打出」的节奏。

### 1.2 STS2 相对 STS1 的新增机制

| 新机制                       | 说明                                                      | 源码位置                                                             |
| ------------------------- | ------------------------------------------------------- | ---------------------------------------------------------------- |
| **Sly（狡黠）**               | 被弃掉时**自动免费打出**                                          | `CardKeyword.Sly`、`AutoPlayType.SlyDiscard`、`CardCmd.cs:188-204` |
| **Eternal（永恒）**           | 该卡**无法被移除 / 转化 / 删除**                                   | `CardModel.IsRemovable => !Keywords.Contains(Eternal)`           |
| **星能 Stars**              | 见上                                                      | `PlayerCombatState.cs:190-209`                                   |
| **免费打出类 Power**           | `FreeAttackPower` / `FreeSkillPower` / `FreePowerPower` | `src/Core/Models/Powers/`                                        |
| **充能球 OrbQueue**          | STS2 全新系统                                               | `PlayerCombatState.OrbQueue`、`CharacterModel.BaseOrbSlotCount`   |

| **附魔 Enchantment**        | 单卡附魔，可改费用 / 伤害                                          | `EnchantmentModel`、`CardModel.Enchantment`                       |

`None, Exhaust, Ethereal, Innate, Unplayable, Retain, Sly, Eternal`

```

TargetType : None, Self, AnyEnemy, AllEnemies, RandomEnemy, AnyPlayer, AnyAlly, AllAllies,
```

> ⚠️ **「迅捷」不是能力**：STS2 里它是**附魔**（`src/Core/Models/Enchantments/Swift.cs`）——
> 被附魔的牌打出时抽 `Amount` 张牌，随即置为 `Disabled`（一次性）。
> 游戏内**没有**「全体友方迅捷 N」这种能力，设计时不要把它当 buff 写。

### 1.5 本工程内的既有约定（必须遵守）

| 约定 | 说明 |
| --- | --- |
| 牌堆遍历先快照 | `PileType.X.GetPile(Owner).Cards.ToList()` 再遍历 —— 直接遍历活集合会在改堆时抛异常（见 `HeidemarieStarTrail` 注释） |
| 「连接」判定用复合属性 | 用 `HeidemarieCard.IsLinked`（静态 `ILinkCard` **或**运行期标记），不要只判接口 |
| 「打出前计数」用快照 | 卡面写了「打出前」的卡读 `ResolveLinkedCountBeforePlay(includeSelf)`，`LinkedCountBeforePlay` 由基类在丢弃**之前**记好 |
| 自动打出不算「直接使用」 | 万剑齐鸣 / 剑冢重放 / 背靠背期间 `SuppressLinkDiscard`；`CardCmd.AutoPlay` 同理 |
| 能力回调要先判归属 | `card.Owner == Owner.Player`（或 `cardPlay.Player == Owner.Player`）+ `Owner.Side == CombatState.CurrentSide` 双判据 |
| 回合末弃牌不派发钩子 | 官方清手牌走 `CardPileCmd.Add`，不触发 `AfterCardDiscarded` —— 「不算回合结束弃牌」的判据天然成立 |
| 升级改关键字用覆盖属性 | 覆盖 `CanonicalKeywords` / `IsLinked` / `IsRestCard` 随 `IsUpgraded` 现算；**不要**在 `OnUpgrade` 里改运行期状态（升级预览会克隆母本，会污染） |
| TargetType 决定指向 | 卡面写「对敌人造成」= `AnyEnemy`；「对随机敌人」= `RandomEnemy`；「对全体敌人」= `AllEnemies` |
| 卡面路径 | `HeidemarieCard.PortraitPath` 取序：① `res://images/packed/card_portraits/heidemarie/<卡牌ID 小写 snake_case>.png` → ② `res://images/atlases/card_atlas.sprites/heidemarie/<id>.tres` → ③ `FallbackPortraitPath`（战士占位）。素材按 PNG 命名丢进目录即生效，**无需打包图集**；⚠️ 不能在 `.tres` 缺失时先返回占位图，否则引擎的 PNG 回落永远走不到（战士占位 `.tres` 是「存在」的） |
| 演出档位 | 攻击牌显式写 `PresentationTier`；技能 / 能力牌由基类按「稀有度 / 费用取更重者」自动算 |
| 卡面词条模板 | 描述开头写 `{KwBlock}`，由 `HeidemarieCardMechanics` 现算；原生关键字（消耗 / 保留 / 固有 / 虚无）**不要**写进模板 |
