# 海德玛丽动画资源落地总流程

本文把《动画与特效清单.md》和《动画组装审计.md》串成一条可执行链路，说明素材如何从 `CNZ_Source` 进入 `CznHeidemarie`，最终由 `.tscn`、JSON 时间轴和运行时合成器播放。

两份原文的职责不同：

- 《动画与特效清单.md》：记录已经接入的角色动画、场景、卡牌触发器、运行时接线和标定结果。
- 《动画组装审计.md》：从 `.srmd/.cfx` 生成的源数据审计，记录每个 effect 组、primitive、z 值、缺失资源和不支持项。

本文是流程入口；源数据数值以审计 JSON 为准，运行时接线以 C# / GDScript 实际代码为准。

---

## 1. 总体数据流

```text
CNZ_Source/czn30093/
  ├─ model_data/30093.srcs       技能/身体动作组装关系
  ├─ model_data/30093.srmd       官方时间轴、effect 组参数、命中与时序
  ├─ effect/*.cfx                 effect 组展开后的 primitive 层级真值
  └─ czn30093-spine_4211/         已转 Spine 4.2.11 的 .skel/.atlas/.png
            │
            ├─ 骨架转换 / 复制 / _skel_data.tres 生成
            ▼
CznHeidemarie/CznHeidemarie/animations/
  ├─ model/                       角色本体
  ├─ effects/                     技能、全屏演出、选人等独立骨架
  ├─ battle_ready/                出牌特写本体
  ├─ portrait/                    选人立绘
  └─ character_select/            角色大厅多层背景
            │
            ├─ tools/extract_cinematic_plan.py
            ▼
CznHeidemarie/CznHeidemarie/
  ├─ cinematic/heidemarie_{ug,ux}.json   全屏演出时间轴
  ├─ effects/heidemarie_moves.json       单体技能特效时间轴
  └─ scenes/**/*.tscn                    场景容器与静态布局
            │
            ├─ AnimLab：检查、预览、调参
            └─ 游戏运行时：C# 触发 + GDScript 按时间轴建 SpineSprite
```

关键原则：`.tscn` 不是全屏特效的“层级真值”。全屏演出的层级和时序来自 `.srmd + .cfx`，`.tscn` 只提供合成器入口；单体特效则由 `heidemarie_moves.json` 提供图层表，`.tscn` 只提供舞台脚本。

## 2. 第一步：确认源素材和权威关系

### 2.1 源文件职责

| 源文件 | 权威内容 | 不应做的事 |
|---|---|---|
| `30093.srcs` | `u1_attack`、`u2_buff`、`u3_attack`、`u4_buff`、`ug_attack`、`ux_attack` 等动作组由哪些身体动画构成 | 不把它当作图层 z 数据 |
| `30093.srmd` | effect 组、类型、`zorder`、坐标、缩放、透明度、延迟、from_guid 播放树、hit | 不手写替代官方时间轴 |
| `effect/*.cfx` | 每个 effect 组内的 primitive/source/z/format | 不按空 z 丢层；空 z 默认是 0 |
| `czn30093-spine_4211/**/*.skel` | Spine 4.2.11 骨骼和动画 | 不再次转换已是 4.2.11 的文件 |
| `czn30093/effect/*.json` | 尚未转成 4.2.11 的原始 Spine 3.8 骨架 | 进入游戏前必须转换 |

### 2.2 三件套检查

每个要渲染的 Spine primitive 必须最终拥有：

```text
<name>.skel
<name>.atlas
<name>.png
<name>_skel_data.tres
```

`particle`、camera、node、color blend 等不是普通 Spine 图层，必须进入 `unsupported` 或专门的适配逻辑，不能伪装成 Spine。

## 3. 第二步：把源骨架落入 mod 工程

### 3.1 已经是 Spine 4.2.11 的资源

从：

```text
CNZ_Source/czn30093-spine_4211/<分类>/<name>.skel
CNZ_Source/czn30093-spine_4211/<分类>/<name>.atlas
CNZ_Source/czn30093-spine_4211/<分类>/<name>.png
```

复制到：

```text
CznHeidemarie/CznHeidemarie/animations/effects/
```

然后生成 `.tres`：

```powershell
.\tools\gen_skel_tres.ps1 `
  -ProjectDir 'G:\sts2Mod\CznHeidemarie' `
  -ResourceDir 'G:\sts2Mod\CznHeidemarie\CznHeidemarie\animations\effects'
```

### 3.2 只有原始 Spine 3.8 JSON 的资源

例如 `ux_attack` 后补资源：

```powershell
$src = 'G:\sts2Mod\CNZ_Source\czn30093\effect'
$dst = 'G:\sts2Mod\CznHeidemarie\CznHeidemarie\animations\effects'
$name = 'heidemarie_30093_ux_attack_01_b1_3'

& 'G:\sts2Mod\tools\SpineSkeletonDataConverter.exe' `
  "$src\$name.json" "$dst\$name.skel" -v 4.2.11
Copy-Item "$src\$name.atlas" "$dst\$name.atlas" -Force
Copy-Item "$src\$name.png" "$dst\$name.png" -Force
```

转换后再为这批 `.skel` 生成 `_skel_data.tres`。输出的 `.skel` 是游戏和 AnimLab 都使用的最终骨架；原始源目录保持只读。

## 4. 第三步：从 `.srmd + .cfx` 生成组装数据

### 4.1 全屏演出

**分两步**：先从源重建（verbose：每层自带全字段），再**瘦身为组键形态**。
只有第 ② 步的产物是运行时读取的文件 —— **跳过 ② 会退回「层信息存两份」的旧形态**。

```powershell
$srmd = 'G:\sts2Mod\CNZ_Source\czn30093\model_data\30093.srmd'
$cfx  = 'G:\sts2Mod\CNZ_Source\czn30093\effect'
$skel = 'G:\sts2Mod\CznHeidemarie\CznHeidemarie\animations\effects'
$converter = 'G:\sts2Mod\tools\SpineSkeletonDataConverter.exe'
$cache = 'G:\sts2Mod\tools\_cinematic_duration_cache.json'

# ① 从 .srmd + .cfx 重建（verbose：每层带 clip / z / offset / scale / opacity / end_ms）
python tools\extract_cinematic_plan.py `
  --srmd $srmd --cfx-dir $cfx --skel-dir $skel `
  --camera-skel-dir 'G:\sts2Mod\CNZ_Source\czn30093-spine_4211\camera' `
  --converter $converter --cache $cache --refresh `
  --command ux_attack `
  --out tools\_raw_ux.json

# ② 瘦身为组键（只留 group / name / start_ms / target / bone_type / official）
python tools\slim_cinematic_layers.py `
  --groups tools\_effect_groups_30093.json `
  --in  tools\_raw_ux.json `
  --out CznHeidemarie\CznHeidemarie\cinematic\heidemarie_ux.json `
  --report tools\_slim_report_ux.md
```

`ug_attack` 同样两步，把上面所有 `ux` 换成 `ug`。

**为什么必须瘦身**：合成器只认组键形态（`HeidemarieEffectGroups.is_keyed()`）。
verbose 形态虽然也能播（脚本有 legacy 分支），但每层的 `z` / `offset` / `scale` / `opacity`
会在时间轴里各存一份，与组库漂移。**判通过的唯一标准是 `--report` 里「不一致 = 0」**。

`--refresh` 在新增或替换骨架后必须使用，否则旧的空时长缓存会继续把新资源判断为不可用。

### 4.2 生成公式

```text
final_z = srmd.effect.zorder + cfx.primitive.z
```

时间不按 primitive 顺序串行播放，而是沿 `from_guid` 播放树推导：

- 同一个父节点的兄弟事件并行起播；
- 各自使用自己的 `delay`；
- `wait_until_end` 只影响子节点相对于父节点的起点；
- `hit` 直接作为命中时间依据。

### 4.3 单体技能特效

`heidemarie_moves.json` 与全屏演出一样，现在是**组键形态**
（`owner` / `target` 里每条只有一个 `group` + `start_ms`），由对照表脚本顺便产出：

```powershell
python tools\audit_animation_mapping.py `
  --mapping tools\_battle_mapping_30093.json `
  --moves   CznHeidemarie\CznHeidemarie\effects\heidemarie_moves.json `
  --spine-json-dir G:\czn30093\effect `
  --cards   CznHeidemarie\Characters\Heidemarie\Cards `
  --out     CznHeidemarie\动画对照表.md `
  --emit-moves CznHeidemarie\CznHeidemarie\effects\heidemarie_moves.json
```

> ⚠️ **不要再跑 `extract_cinematic_plan.py --command moves-z`**。
> 那是旧「逐层」方案的回填器：它假定 `moves.json` 里每层都有 `z` 字段逐个改写，
> 而组键版没有 `z` —— 跑下去要么报错，要么把文件写坏。

`--moves` 与 `--emit-moves` 指向同一个文件是**故意**的：脚本先把整份读进内存
（`moves` 只用来取卡牌清单与 `note`），再写回，读在写之前，安全。
`--emit-moves` 的输出就是最终产物，不需要再手工复制。

这里的 `owner` / `target` 是运行时挂载桶：

- `owner` 挂到施法者单位的前台特效容器（世界坐标用 `BodyOrigin`）；
- `target` 挂到目标单位的前台特效容器（世界坐标用 `GetBottomOfHitbox() + (0,-40)`）；
- 同一张牌只创建一套 owner/target 舞台；
- 只有官方明确的目标效果才可以按多个目标复制。

**起播时刻是生成期算好的**（= 动作链累计偏移 + `.srmd` 的 effect delay + 组内该层 delay），
运行时不用再自己推链。源里 `attack_play1` 的 effect delay 是 0，但它的起播是 200ms
—— 因为前面 `attack_ready` 已经播了 200ms。

## 5. 第四步：审计和完整性门禁

运行：

```powershell
python tools\audit_cinematic_assets.py `
  --source-root CNZ_Source\czn30093 `
  --project-root CznHeidemarie\CznHeidemarie `
  --out-dir CznHeidemarie\CznHeidemarie\cinematic
```

它会生成两张**路线级审计 JSON**（逐组 primitive 真值）：

- `heidemarie_ug_attack_assembly_audit.json`
- `heidemarie_ux_attack_assembly_audit.json`

> ⚠️ `CznHeidemarie/动画组装审计.md` 自 2026-10-15 起**改由另一个脚本产出**：
> `python tools\audit_assembly_overview.py`（覆盖组库 / 单体特效 / 全屏演出 /
> 出牌特写 / 选人三档）。两个脚本各管各的产物，不要互相覆盖。

当前 `ux_attack` 的正确口径是：

```text
effect 组：4
primitive：42
Spine 图层：41
particle：1
缺失 Spine 资源：0
重复 source：0
最终 z：-10000..1001
```

这里“42”是全部 primitive，“41”是 AnimLab/游戏可直接渲染的 Spine 层；不要把 particle 计入 Spine 层数。

### 门禁规则

| 检查 | 结果 | 处理 |
|---|---|---|
| Spine 缺 `.skel/.atlas/.png/.tres` | 失败 | 不生成可播放路线，补齐资源后重跑 |
| `.cfx` 出现 `particle` | 记录 | 不当作 Spine 组装；AnimLab 当前不渲染 |
| source 重复 | 失败 | 检查是否重复展开或重复事件 |
| z 缺失 | 失败/警告 | 空 z 按 0，不能直接丢弃 primitive |
| JSON layers 为空 | 失败 | 回退原生演出 |

游戏侧 `heidemarie_cinematic_stage.gd` 对 `missing` 非空的路线会整段拒绝，避免“缺几层仍然硬播”的半成品演出。

## 6. 第五步：场景和运行时如何消费数据

> 本节是**契约**：重建时必须满足什么（节点类型、接管层、坐标、闸门）。
> **本工程的实际接线**（哪个类挂在哪个 Hook、完整调用链、伤害时机对表、
> 战斗中的开关）在 `动画与特效清单.md` §七 / §八 —— 那是**现状**，随代码变；
> 本节是**原则**，不随代码变。两者不要互相抄。

### 6.1 全屏演出

```text
卡牌
  → HeidemarieCinematicRuntime
  → heidemarie_cinematic_stage.tscn
  → heidemarie_cinematic_stage.gd
  → 读取 heidemarie_ug/ux.json
  → 每个 Spine layer 动态创建 SpineSprite
  → 通过 z 保序压缩到 Godot [-4000,4000]
```

要求：

- 根节点是 `CanvasLayer`，接管层为 4090；
- `SCREEN` 和 `STAGE` 同在一个 canvas；
- 每个 SpineSprite 必须 `z_as_relative = false`，否则两棵子树无法交织；
- 黑幕低于所有演出层；
- 本体隐藏/归还由 `actors_restored` 控制；
- 命中由 `hit_reached` 控制；
- 结束由 `stage_finished` / `resources_finished` 控制。

`.tscn` 本身不列出 41 个全屏图层；它只承载舞台脚本。图层清单在 JSON。

### 6.2 单体技能特效

```text
CardPlayEnqueuingEvent
  → HeidemarieMoveEffectsRuntime
  → heidemarie_effect_stage.tscn
  → 读取 heidemarie_moves.json 的 card/owner/target
  → 挂到 creature.GetVfxContainer()（世界坐标）
  → finished 后 QueueFreeSafely 释放
```

单体特效不是全屏画布，不需要 1280×720 坐标换算；它用世界坐标定位，并由 C# 复刻目标 `Body` 的全局缩放 / 镜像。

## 7. 第六步：AnimLab 验证

AnimLab 不是源数据生成器，而是最终 JSON/骨架的可视化检查器：

1. 选择包含目标 `.tscn` 的场景根目录；
2. 工具递归扫描目录下的 `.tscn`；
3. 场景下拉显示扫描结果；
4. 选择全屏舞台时，读取同目录的 `heidemarie_ug.json` / `heidemarie_ux.json`；
5. 直接读取 `animations/**/*.skel + .atlas`，不依赖 `.tres` 导入缓存；
6. 用滑条检查每个时间点、层级、clip、offset、scale、opacity；
7. 新增资源后重启 AnimLab，或点击“重新扫描”刷新骨架索引和预览缓存。

AnimLab 当前不能渲染 `particle/CZNFX`、camera、node 等非 Spine 内容。因此预览比官方原演出少粒子或镜头效果，并不代表 Spine 图层缺失。
