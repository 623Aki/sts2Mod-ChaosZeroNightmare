## 〇、核心结论

1. **关键字「行为」与「显示」分离**：行为写在卡牌/Power 的钩子里；显示用
   `CznCore.Cards.CardMechanicDefinition` + `CardMechanicPresentation`（本工程已自带）。
2. **原版 `CardKeyword` 8 个值**（`Entities/Cards/CardKeyword.cs:18`）：
   → **消耗/虚无/保留/无法使用 = `Exhaust`/`Ethereal`/`Retain`/`Unplayable`，零代码**；
   其余 8 个自研。
3. **「墓地」= `PileType.Discard`（弃牌堆）**；安息里的「已使用牌堆」**就是墓地**，
   限制范围 = **本回合内不许把它从墓地拿走**。
4. **稀有度含义**：`Basic` = 仅初始卡组（奖励/商店/战斗生成全排除）；`Common` = 可正常获取；
   `Token` = 衍生牌（奖励/商店取不到，但**战斗内随机生成会抽到**，可加 `CanBeGeneratedInCombat => false` 禁掉）。
5. **`CardTag.Strike` 是纯元数据**：只影响 `PerfectedStrike`/`StrikeDummy`/`HellraiserPower` 等
   「打击协同」。我们的牌都不是打击 → **都不带 `Strike`**。

## 二、关键字实现方案（8 个）

> 建议收敛到 `HeidemarieCard` 基类：定义接口 + 基类一次重写钩子分派（参考 `NineCard.cs:138`）。

| 关键字 | 触发点 | 实现 | 档 |
|---|---|---|---|
| **感应** | `AfterCardDrawn`（`AbstractModel.cs:410`） | 抽到本牌 → 执行感应效果 | ✅ 直接复用 |
| **链接** | `OnPlay` 开头 | 手牌中**其他所有带「链接」的牌**全部 `CardCmd.Discard` | ⚠️ 需改造 |
| **安息** | `AfterCardDiscarded`（`:384`）+ 本回合锁定墓地 | 前半：丢弃时发动效果；后半：本回合禁止把它移出墓地 | ⚠️ 需自研（轻量） |
| **守墓** | `ModifyShuffleOrder`（`:1887`） | `cards.Remove(this)`（`PerfectFit.cs` 反向） | ✅ 直接复用 |
| **回收 N** | `AfterCardChangedPiles`（`:359`） | 进墓地且 N>0 → `Add(this,Hand)`，N−1 | ⚠️ 需自研（有范例） |
| **终结** | `OnPlay` 末尾 | `PlayerCmd.EndTurn(Owner,false)`（**仅打出时生效**） | ✅ 直接复用 |
| **唯一** | 加牌入口 | 卡组内同名仅 1 张；禁复制/重放 | ❌ 需自研 |
| **焚烧** | `AfterCardExhausted`（`:447`） | 本牌被消耗时触发（照抄 `NineCard.OnBurn`） | ✅ 直接复用 |

### 2.1 感应 ✅
- 基类 `override AfterCardDrawn` → `this is IHeidemarieSenseCard s` → `s.OnDrawTrigger(ctx)`。
- 范例：`NineOffset.cs`、原版 `Cards/Void.cs` / `KinglyKick.cs`。
- 去向按文档：剑雨 → **抽牌堆**；安魂剑 → **手牌**。

### 2.2 链接 ⚠️
- **语义**：`直接使用此卡时，丢弃手牌中其他所有带「链接」的牌`（自动、无选择）。
- **实现**：`foreach (var c in PileType.Hand.GetPile(Owner).Cards.Where(c => c != this && c 带链接).ToArray()) await CardCmd.Discard(ctx, c);`
- **联动**：被丢的牌触发 **安息**（`AfterCardDiscarded`）、**回收 / 极光之光计数**（`AfterCardChangedPiles`）→ 整套引擎核心。
- 范例：`TipheraCreationDraw.cs:28`。

### 2.3 安息 ⚠️（风险已降）
- **澄清（v3）**：「不能移出」= **本回合内**不许把它从**墓地**拿走。
- **前半**：`AfterCardDiscarded` 判 `card == this` → 执行效果。
- **后半**：安魂剑**无回收**，当前也无任何效果能把它从墓地取走（剑冢只取极光剑）→ **实战影响≈0**；
  先用**轻量方案**：本卡打「本回合安息锁定」标记，在**我方**取墓地辅助里过滤；不写 Harmony。
  日后若要全局生效再上 Harmony `CardPileCmd.Add` 拦截（**原版无「阻止移堆」钩子**）。
- 清除时机：回合结束清标记。

### 2.4 守墓 ✅
- `if (!isInitialShuffle && cards.Contains(this)) cards.Remove(this);`（模板 `PerfectFit.cs:10-17`）。

### 2.5 回收 N ✅
- **语义（v3）**：`回收 N` —— 牌每进墓地一次回手，然后 **N−1**；N 归零后不再回手。
- **层数默认 1**；**显示规则**：N=1 只显示「**回收**」，N>1 显示「**回收N**」（如「回收2」）。
- **实现**：卡实例存 `int` 计数；`AfterCardChangedPiles` 判进墓地且 N>0 → `Add(this,Hand)`，N−1。
- **显示（2026-10-13 落地）**：卡面文本改为**模板参数**，由
  `HeidemarieCard.AddExtraArgsToDescription` → `HeidemarieCardMechanics.AddCardTextArguments`
  在渲染时现算，因此能跟着运行期状态走。每个词条三种形态：
  `{Link}`（「链接。」）/ `{LinkLine}`（自带前缀换行，整条可缺省）/ `{LinkName}`（「链接」）。
  「回收」的文本按层数现算（1 层 →「回收」，N>1 →「回收N」），
  没有回收时参数为空串，整行消失（`cards.json` 里 `{GraveKeep}{RecycleLine}`）。
- **⚠️ 赋值的时序**：卡面文字只在卡片节点建立时（`NCard.UpdateVisuals` → `GetDescriptionForPile`）
  读一次词条状态，而悬停提示是每次悬停即时算的。所以「凝锋」必须在极光剑**入堆之前**
  写好 `RecycleRemaining`（`GenerateAuroraSwords(..., grantedRecycle)`），
  否则会出现「提示里有回收、卡面上没有」的错位。
- 范例：`Relics/LuckyFysh.cs`、`Powers/AggressionPower.cs`、`Cards/Hologram.cs`。
- **「赋予其回收」**（凝锋给生成牌挂回收，**默认 1 层**）：`HeidemarieCard.RecycleRemaining`
  直接写在卡实例上（不再需要 `ConditionalWeakTable` + Harmony）。

### 2.6 终结 ✅
- **语义（v3 澄清）**：**仅打出时**生效；打出后 = **手动结束回合**，走游戏原生回合结束逻辑。
- 实现：`OnPlay` 末尾 `PlayerCmd.EndTurn(Owner, false)`（`PlayerCmd.cs:278`）。范例 `NineSheathe.cs:43`。
- **被丢弃（安息）时不触发终结**。

### 2.7 唯一 ❌（范围=当前卡组）
- **语义（v3）**：**卡组内**同名仅 1 张；**不能复制**、**不能附加「重放/重复」类效果**。
- 原版无张数限制（`CardKeyword.Eternal` 只管移除）→ 自研：标记接口 `IHeidemarieUniqueCard` +
  奖励/商店/事件**加牌入口过滤**（Harmony）+ 复制/变形/重放入口过滤。
- **解放极光额外**：只能由极光之光获得 → 设 `CanBeGeneratedInCombat => false` 且
  `CanBeGeneratedByModifiers => false`，由极光之光自己 `AddGeneratedCardToCombat`（不受这两开关限制）。

### 2.8 焚烧 ✅
- `override Task AfterCardExhausted` 判 `card == this` → 触发。照抄 `NineCard.cs:138-176`。

## 三、伤害公式与百分比增伤（⚠️ 引擎级注意）

**目标公式（v3 确认）**：

```
最终伤害 = (原基础伤害 + 固定伤害增加) × (1 + 0.5 + 其他百分比伤害增加)
           └── 加算区：UpgradeValueBy / ExtraDamageVar / ModifyDamageAdditive
                                              └── 增伤区：所有百分比「相加」后作为单一因子
```

**⚠️ 引擎现状**：乘算区是**连乘**，不是相加 —— `Hook.ModifyDamageInternal`（`Hooks/Hook.cs:2535-2546`）：

```csharp
foreach (var item2 in ...) { decimal num3 = item2.ModifyDamageMultiplicative(...); num *= num3; }
```

⇒ 若「剑光 +50%」与「绝响 每剑 +100%」**各做成一个乘算 modifier**，结果 = `1.5 × (1+N)`，
**不等于** 你要的 `1 + 0.5 + N`。

**方案（建议）**：所有百分比增伤**汇聚到一个「百分比增伤池」能力**（内部 `Amount` = 累计百分点），
由**它自己单独**提供乘算因子 `1 + Amount/100`（池里没有别的乘算 modifier 时，结果就是 `1+Σ百分比`）。
- 剑光感应：`+50` 入池，下一张攻击命中后用 `AfterAttack` 清掉（参考 `Powers/VigorPower.cs`）。
- 绝响/解放极光：结算前把 `+100×数量` 入池，命中后清掉。
- 使用者需确认：**原版别的百分比增伤（如易伤 Vulnerable 的 1.5×）是否仍按连乘**（本方案下它们会另乘，属既有机制）。

（替代方案：绝响/解放极光把倍率烘进自己的 `CalculatedDamageVar`，剑光用独立 modifier —— 但仍是连乘，**不满足公式**，故不推荐。）

## 四、能力（Power）方案

### 4.1 极光之光 ✅ 骨架可抄
- **效果**：层数达 **3** → 把**解放极光**加入手牌；同时**移除**「凝聚极光」和**所有**「极光之光」。

- **移除范围（建议）**：**全部战斗牌堆**（Hand+Draw+Discard+Exhaust+Play），彻底断循环。**待确认**。

### 4.2 剑光「感应：下一张攻击牌 +50%」⚠️

## 九、「唯一」关键字拦截（2026-10-13 完成）

实现文件：`Registration/HeidemarieUniquePatch.cs`。
判定范围 = **当前卡组**（卡组内已有同 Id 的另一张即视为已持有）。

| 入口 | 拦截方式 |
|---|---|
| 奖励 / 事件 / 遗物加牌 | Postfix `CardCreationOptions.GetPossibleCards` → 从候选里剔除已持有的唯一牌 |
| 商店 | Postfix `Hook.ModifyMerchantCardPool` → 同上 |
| 变形 | Postfix `CardFactory.GetDefaultTransformationOptions` → 从变形目标里剔除 |
| 战斗内随机生成 | `HeidemarieCard.CanBeGeneratedInCombat => this is not IUniqueCard` |
| 复制 / 直接塞牌 | 手动挂载 Prefix `CardPileCmd.Add(cards, newPile, …)` → 目标为卡组且已持有同 Id 时丢弃并告警（安全网） |
| 重放赋魔 | Postfix `CardModel.GetEnchantedReplayCount` → 唯一牌恒返回 0 |
| 重放结算 | Postfix `Hook.ModifyCardPlayCount` → 唯一牌强制压回 1 次 |
| 重放消耗 | Prefix `Hook.AfterModifyingCardPlayCount` → 唯一牌跳过，**不消耗**这次加成，留给下一张牌 |

> 「加牌去重」补丁需要按参数类型精确指定重载、并改写异步返回值，是唯一可能挂载失败的补丁，
> 因此改为在 `MainFile.Initialize` 里**单独挂载**（`HeidemarieUniqueDeckGuard.Install`），失败只告警；
> `Harmony.PatchAll()` 也加了 try/catch，避免单个补丁失败导致整个 mod 加载失败。

## 十、目标类型（`TargetType`）调整（2026-10-13）

两张卡的指向性联动修改：`极光剑` 由**指向**改为**随机**，`剑冢` 随之改为**非指向**。

### 10.1 改动对照

| 卡牌 | 改动前 | 改动后 | 关键代码 |
|---|---|---|---|
| 极光剑 `HeidemarieAuroraSword` | `TargetType.AnyEnemy` + `.Targeting(cardPlay.Target)` | `TargetType.RandomEnemy` + `.TargetingRandomOpponents(CombatState!)` | `Characters/Heidemarie/Cards/HeidemarieAuroraSword.cs` |
| 剑冢 `HeidemarieSwordTomb` | `TargetType.AnyEnemy`，`OnPlay` 里 `ArgumentNullException.ThrowIfNull(cardPlay.Target)` | `TargetType.None`，`OnPlay` 不再取目标 | `Characters/Heidemarie/Cards/HeidemarieSwordTomb.cs` |
| 共享动作 `PlayAuroraSwordsFromDiscard` | 签名带 `Creature? target`，`AutoPlay(ctx, sword, target)` | **移除 `target` 参数**，`AutoPlay(ctx, sword, null)` | `Characters/Heidemarie/Cards/HeidemarieCardActions.cs` |

### 10.2 为什么这样切

- `TargetType.RandomEnemy` 的官方写法就是 `TargetingRandomOpponents(combatState)`
  （对照本体 `Ricochet.cs` / `SwordBoomerang.cs` / `Volley.cs`），本项目照抄，
  与 `HeidemarieFinalEcho` 的 `TargetingAllOpponents(CombatState!)` 同一风格。
- `cardPlay.Target` 对 `RandomEnemy` 恒为 `null`（`CardPlay.Target` 文档：
  "Null for un-targeted cards"），所以 `OnPlay` 里的空检查必须删掉，否则直接抛异常。
- `CardCmd.AutoPlay` 的「目标为空则随机补一个」分支**只对 `AnyEnemy` / `AnyAlly` 生效**
  （`CardCmd.cs:73-97`）。因此 `剑冢` 重放 `RandomEnemy` 的极光剑时传 `null` 是安全的：
  游戏不会替它补目标，随机目标完全由极光剑自己的 `TargetingRandomOpponents` 承担。
- `AutoPlay` 会先把牌移进 `PileType.Play` 再调 `OnPlayWrapper`，
  所以 `OnPlay` 里 `CombatState` 一定非空，用 `CombatState!` 安全。

### 10.3 行为变化

- 极光剑每次打出命中一名**随机**敌人；`剑冢` 重放 N 张时每张独立取随机，
  **允许重复命中同一个敌人**（`TargetingRandomOpponents` 的 `allowDuplicates` 默认为 `true`）。
- `剑冢` 出牌不再触发选目标交互，也不再因「无可选敌人」而进入待选状态；
  场上敌人全灭时 `TargetingRandomOpponents` 取到空集合，伤害自然落空（不报错）。
- 本地化 `cards.json` 已先行改为
  `HEIDEMARIE_AURORA_SWORD.description` = 「对随机敌人造成…」、`HEIDEMARIE_SWORD_TOMB.description` =
  「打出墓地中最多{Swords:diff()}张极光剑。」，与本节一致。
