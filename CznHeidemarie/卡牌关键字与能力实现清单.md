### 2.9 运行期关键字「临时连接 / 临时安息」✅ 已实现

- **载体**：`HeidemarieCard.RuntimeLinkedThisTurn` / `RuntimeLinkedThisCombat` / `RuntimeRestThisCombat`；
  复合判定 `IsLinked` / `IsRestCard`（静态接口 **或** 运行期标记）。
- **范围**：描述含「本回合」→ 本回合有效（`AfterPlayerTurnStart` 清除）；否则 → 本场战斗有效
  （战斗牌堆每场战斗使用独立卡实例，天然重置）。
- **移除**：只清运行期标记，**不动**初始自带「连接」的牌。
- **连带丢弃（派发点）**：统一由 `HeidemarieCard.BeforeCardPlayed` 调用
  `HeidemarieCardActions.DiscardOtherLinked` —— 原生连接与运行期临时连接走同一条路，
  从墓地重放、被别的效果自动打出同理。
- **抑制**：`HeidemarieCardActions.SuppressLinkDiscard` 供两类场合临时抑制
  「万剑齐鸣」（连续打出多张连接牌）与「剑冢」（重放不算「直接使用」）；
  两处都「进出各存一次原值」，嵌套时能正确还原。
- **计数口径**：`LinkedCountBeforePlay` 由 `BeforeCardPlayed` 在丢弃**之前**取快照（不含自身）；
  `HeidemarieCard.ResolveLinkedCountBeforePlay(includeSelf)` 由各卡按卡面文案决定是否 +1 ——
  **描述写了「打出前」→ 含自身**（一缕光芒 / 叠光奏浪 / 万剑诀），描述没写则不含自身。
  底层统计仍是 `HeidemarieCardActions.CountLinkedInHand(self, includeSelf)`。

### 2.11 卡面词条渲染：公共占位符 `{KwBlock}` ✅

**问题**：`缀星` / `微光` / `冥渡` / `撷光` / `引锋召刃` / `万众英雄` 会给**任意牌**临时赋予
「连接」（`北极圈` 升级则给自己「安息」）。但引擎只在**模板引用了占位符**的位置替换文本 ——
没写 `{Link}` 的牌，被赋予后卡面不会显示「连接。」。

**做法（公共，勿再逐张写 `{Link}`）**：

- 所有卡的 `cards.json` 模板统一在最前面写一个 **`{KwBlock}`**；
- `HeidemarieCardMechanics.AddCardTextArguments` 每次渲染时按 `For(card)` 现算该块：
  本牌当前生效的「独立成行词条」（**连接 / 安息 / 守墓 / 回收 / 终结 / 唯一**）
  按稳定顺序拼成一整块，**末尾自带换行**；无词条时整块（含换行）一起消失 → **不留空行**。
- 「回收」带层数（1 层「回收」、N>1「回收N」）由 `BuildRecyclePlainName` 现算，一并进块，
  避免与金色标签被拆开。
- **不进块的两个词条**：`感应`、`焚烧` —— 它们永远配
  `{SenseName}：卡面专属说明` / `{BurnName}：…` 使用（仍走逐词条参数）。

**收益**：新增关键字只改 `HeidemarieKeywords` + `HeidemarieCardMechanics.For`；
新增卡只写 `{KwBlock}`；运行期临时赋予的连接 / 安息自动上卡面（悬停提示本就已公共）。

**兼容**：逐词条占位符 `{Link}` / `{Link}` / `{LinkName}` / `{LinkLine}` 仍保留可用，
供「词条名 + 卡面专属说明」写法使用；但**不要与 `{KwBlock}` 同时用于同一词条**（会重复显示）。

## 三、能力（Power）方案（全部已实现）

### 3.1 白昼 ✅

- 实现文件：`Powers/HeidemarieDaylightPower.cs`。
- **只负责层数与生命周期**：首次获得时「确保」极光剑增伤区存在（幂等），
  自己不再提供乘算因子；因子统一由 `Powers/HeidemarieAuroraDamagePoolPower.cs` 给。
- 打出极光剑后清除。
- **极光剑「被丢弃时」的伤害同样视为一次极光剑结算**：吃增伤并在结算后消耗本能力。
  主动打出路径由 `AfterAttack(AttackCommand)` 清除；丢弃伤害走 `CreatureCmd.Damage`（非 AttackCommand），
  因此由 `HeidemarieAuroraSword.DealDiscardDamage` 末尾 `PowerCmd.Remove<HeidemarieDaylightPower>` 自己清。

### 3.2 极夜 ✅

- 实现文件：`Powers/HeidemarieNightPower.cs`。
- **只负责层数与生命周期**：首次获得时「确保」极光剑增伤区存在（幂等）；下个我方回合开始清除。
- 与白昼的「相加」在极光剑增伤区一处完成，因此这里**不再需要**「有白昼就让位」的判定。

### 3.3 北极圈 ✅

- 实现文件：`Powers/HeidemarieNorthPolarPower.cs`（回合开始生成 **2 × 层数** 张极光剑；
  层数为 `StackType.Counter`，多次打出「北极圈」叠加）。
- 升级档「赋予关键字**安息**」作用于**卡牌本体**，不是生成的剑：
  - `HeidemarieNorthPolar.IsRestCard` 覆盖为 `base.IsRestCard || IsUpgraded` ——
    升级后卡面显示「安息」词条（`cards.json` 描述以 `{RestLine}` 收尾），
    并被「冥渡」等按 `IsRestCard` 判定的卡牌识别；
  - 丢弃时走 `HeidemarieCard.AfterCardDiscarded` → `OnRestEffect`，
    与打出共用 `ApplyNorthPolar`（同样获得「北极圈」能力）+ 本回合锁墓。
- 能力生成的极光剑**不带任何额外关键字**；旧实现用标记能力
  `HeidemarieNorthPolarRestPower` 把「安息」传给生成的剑，**已移除该标记能力**。
  极光剑的「被丢弃时造成伤害」是本牌自带效果（见 §4.5），不由「安息」承担。

### 3.4 ⚠️ 加算约束（已按此实现）

引擎乘算区为连乘（`Hook.ModifyDamageInternal`：`num *= num3`）⇒ 同一「增伤区」里的百分比
**必须共用同一个 modifier**，否则会退化成连乘 `(1+a)(1+b)`。本 mod 现有两个增伤区：

- **极光剑增伤区**（白昼 / 极夜）⇒ 由 `Powers/HeidemarieAuroraDamagePoolPower.cs` 单独提供
  `1+(白昼+极夜)/100`，且只对极光剑生效。
- **全局百分比增伤池**（连接牌数 / 墓地极光剑数等）⇒ 由 `Powers/HeidemarieDamagePercentPower.cs`
  单独提供 `1+Amount/100`，对所有强化攻击生效。

### 3.5 极光之光 ✅

- `Powers/HeidemarieAuroraLightPower.cs`（阈值 3；达标 → 解放极光入手 + 清全部战斗牌堆的凝聚极光 + 清所有极光之光）。

### 3.6 百分比增伤池 ✅

- `Powers/HeidemarieDamagePercentPower.cs`（隐藏；因子 `1 + Amount/100`）。
- 使用者：绝响、解放极光、一缕光芒。
- **生命周期改由调用方显式管理**：`InjectAsync`（入池）/ `ClearAsync`（清池）。
  卡牌统一走基类 `HeidemarieCard.WithPercentDamageBoost(choiceContext, 百分点, 攻击逻辑)`，
  由它用 `try/finally` 保证攻击结束后一定清池。
- 为什么不再由钩子自动清：`AttackCommand.Execute` 有若干「还没走到 `Hook.AfterAttack`
  就提前 return」的分支（攻击者死亡 / 战斗结束等），靠 `AfterAttack` 清池会把这些情况
  漏成「池残留到下一次攻击」（白嫖增伤）。
