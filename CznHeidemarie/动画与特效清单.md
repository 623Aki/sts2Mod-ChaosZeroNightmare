### 3.1 剑影环绕（待机特效层）

立绘前后各挂一层特效，构成「剑影环绕」。接线走 CznCore 预留的  
`BattleReadyOverlayProfile.IdleEffect`（机制见 `参考mod动画实现清单.md` 9.1）。

场景：`scenes/heidemarie_battle_ready_effects.tscn`  
（根 `Node2D` + `Back` / `Front` 两个子树，运行时被拆出来分别挂到立绘骨架的后面 / 前面）

| 层       | 骨架                                     | z_index | 循环时长(s) | 说明          |
| ------- | -------------------------------------- | ------- | ------- | ----------- |
| `Back`  | `heidemarie_30093_ug_aura`             | 0       | 4.67    | 终结技光环（环绕底色） |
| `Front` | `heidemarie_30093_sword_eff_g`         | 0       | 4.13    | 剑刃辉光（无实体剑刃） |
| `Front` | `heidemarie_30093_eff_casting_ready_b` | 1       | 1.33    | 施法待机光效      |

> 三份骨架都只有单段 `animation`，循环播放，因此「时长」不影响观感，只作为参考。  
> 旧稿把 `ug_aura` / `eff_casting_ready_b` 记成 2.00 / 2.67，实测是 **4.67 / 1.33**。

> **已移除 7 层（均为剑 / 指向射线，做环绕会露出剑尖）**：  
> `heidemarie_30093_battle_ready_eff_b`、`_b_mask`、`_f`、`_f_mask`、`_mask`、  
> `heidemarie_30093_sword_eff_b`、`_f`。  
> 其中 `battle_ready_eff_*_mask` 是纯红（`ff0000ff`）的下指大剑，  
> `battle_ready_eff_b/_f` 与 `sword_eff_b/_f` 的图集里都是大剑 + 带箭头的长射线。

- 全部循环播 `animation`；`RootPosition = (0,0)`、`RootScale = 1`  
  —— 这几层骨架与立绘骨架同属一套坐标单位，运行时又挂在立绘骨架节点下，**原点即贴合**。
- 容器自身的 position/scale 会被 CznCore 重置，所以层内摆放只靠 `z_index`。
- 每次立绘重新显示都会重播一次（`StartIdleEffects`），否则会停在上次播完的帧。

> （`root → pivot(y=6.95, scale=0.5154) → char/bg/mid/pillar1~4`），它们是**同一张 cut-in 的三层切片**，
> `.cfx` 里三层的 `x`/`y`/`scale` 全为空（= 默认 0/1）。原稿给的是三套不同值
> （2.06/2.05/2.01 与 1180/1299/1415），会让三层互相错位，已改成统一值。

> 目标高度撑满画面、水平中心落在设计坐标 x≈1180（与「动态立绘」的人物同一列，都靠右）：
> `scale = 1080 / 872.17 = 1.24`、`X = 1180 − 956.61 × 1.24 / 2 = 587`、`Y = 1080`（画面底边）。待实机微调。

> 场景里节点按「后→前」树序排列，**并显式给 `z_index`（1/2/3）** —— 背景是不透明场景图，
> 必须确保三层一定压在它之上。

> `illust_3`（花2 + mid + 石柱1~4）与 `bg_1` 自带的柳树/圆台会形成「两层景」；
> 若不想要，把该节点 `visible` 置 false 即可（变换不用动，三层共用同一套值）。

> 这三张骨架**只被选人界面使用**，`heidemarie_ux.json` 里并不含它们

### 4.4 布局与运行时的三个要点

1. **设计坐标**：立绘类变体里 SpineSprite 的 `position` / `scale` 都按 **1920×1080** 标注，

   `metadata/czn_portrait_skin`（皮肤名）、`metadata/czn_portrait_animation`（逗号分隔，末段循环）。

### 7.2.1 伤害时机对表（命中闸门 / 收尾闸门）

原生 `AttackCommand.Execute` 的节奏是「触发施法者动作 → 等 `waitTime` → 结算伤害」，  
而 `waitTime` 只服务于原生骨架动作，与演出时间轴无关。演出开始后原生动作被黑幕接管，  
于是伤害总是抢在动画前面落地 —— 这正是「先出伤害再出动画」的根因。

对齐办法与两个参考 mod（Nine 的 `TryWaitForHit` / Tiphera 的 `TryGetCoveredBodyWait`）一致：

| 环节 | 补丁                               | 行为                                                                   |
| -- | -------------------------------- | -------------------------------------------------------------------- |
| 命中 | `CreatureCmd.TriggerAnim` Prefix | 触发器是 `XAttack` / `GAttack` 且演出在跑时，把「等 `waitTime`」换成「等 `hit_reached`」 |
| 收尾 | `Hook.AfterAttack` Postfix       | 把 `Hook.AfterAttack` 的返回值接到舞台收尾上，整段演出播完才结束这次出牌                       |

两道闸门都由 `Phase` 里的 `TaskCompletionSource` 承载，**取消 / 降级 / 看门狗超时都会在  
`End()` 里无条件放行**，不会把出牌吊死；演出不存在或已降级时闸门不生效，走原生等待。
