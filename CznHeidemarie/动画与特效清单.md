### 4.1 立绘（`StaticPortrait`）

`破军(ux)全屏演出用的三张官方插画骨架`（**纯角色，无背景图**），三张都按 `intro → loop` 播放
（由 `metadata/czn_portrait_animation = "intro,loop"` 声明，运行时执行）。

| 项                  | 值                                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| 场景                 | `scenes/screens/char_select/heidemarie_static_portrait_bg.tscn`                                               |
| 背景                 | **无**（底图交回游戏选人界面自己的背景；图片资源仍在 `images/character_select/heidemarie_select_bg_30093_1.png`）                      |
| 素材                 | `CznHeidemarie/animations/effects/heidemarie_30093_ux_illust_{1,2,3}.{skel,atlas,png}` + 各自 `_skel_data.tres` |
| 皮肤 / 动画            | 单一皮肤 `default`；每张 2 段动画 `intro` / `loop`                                                                      |
| 层序（后→前）            | `illust_3`（z=1）→ `illust_2`（z=3）→ `illust_1`（z=4）                                                             |
| 标定（1920×1080 设计坐标） | 三层**共用** `position (1186, 542)`、`scale 0.54`（居中偏右，让开描述文本）                                                     |

> 三张骨架的骨骼树完全相同，是同一张 cut-in 的三层切片，因此**必须共用同一套变换**，
> 否则三层会互相错位。
> 骨架原点在内容中部（pivot 处），**不在包围盒左下角**。
> 屏幕映射关系为 `屏幕 y = Y − scale × y`（Spine y 向上）。要更大就继续等比调大 `scale`，
> `X` 按每 0.1 scale 约 +85 跟进（保持左缘位置）。
> 背景层 `illust_3` 的石柱 / 花会直接落在游戏自己的背景上；不需要时把该节点 `visible` 置 false。
> 这三张骨架**只被选人界面使用**，`heidemarie_ux.json` 里不含它们。

> `Hook.BeforeAttack` 调用，是「攻击指令已组好、骨架动作还没播、伤害还没结算」的时刻，
> 只有拿到 `AttackCommand` 才能做「可击杀敌人才播」的致死预判。

### 7.2.1 伤害时机对表（命中闸门 / 收尾闸门）

原生 `AttackCommand.Execute` 的节奏是「触发施法者动作 → 等 `waitTime` → 结算伤害」，
而 `waitTime` 只服务于原生骨架动作，与演出时间轴无关，伤害总是抢在动画前面落地。
对齐办法与两个参考 mod（Nine 的 `TryWaitForHit` / Tiphera 的 `TryGetCoveredBodyWait`）一致：

| 环节 | 补丁                               | 行为                                                                   |
| -- | -------------------------------- | -------------------------------------------------------------------- |
| 命中 | `CreatureCmd.TriggerAnim` Prefix | 触发器是 `U3Attack`（剑之乐园）/ `GAttack`（解放极光）且对应演出在跑时，把「等 `waitTime`」换成「等 `hit_reached`」 |
| 收尾 | `Hook.AfterAttack` Postfix       | 把 `Hook.AfterAttack` 的返回值接到舞台收尾上，整段演出播完才结束这次出牌                       |

两道闸门都由 `Phase` 里的 `TaskCompletionSource` 承载，**取消 / 降级 / 看门狗超时都会在
`End()`** **里无条件放行**，不会把出牌吊死；演出不存在或已降级时闸门不生效，走原生等待。

## 九、手牌连接光带（非骨架 · 程序化）

> 与前面八节**不同类**：这一节没有任何 Spine 骨架，所以
> `动画资源到最终场景落地流程.md` 那套「骨架 → 场景 → 组库」的流程**不适用**。
> 它是运行时用**着色器 + 网格 + 粒子**现算出来的效果。

### 9.1 是什么

手牌里带「连接」关键字的牌，按手牌顺序两两相邻连成一条链，在相邻两张牌的
**顶边中点**之间向上拱起一条流动光带，光带上贴着三角碎片粒子小幅上下浮动。

| 组成 | 实现 |
|---|---|
| 光带 | 两层 `MeshInstance2D`：外层光晕（厚、淡、柔、无脉冲）+ 主线（薄、亮、带自左向右扫过的脉冲）；曲线由 C# 每帧采样成三角条带写进网格 |
| 粒子 | 每条光带一簇 `Sprite2D`，贴 `tri_pati_01`，沿曲线**法线方向**小幅上下浮动（任意时刻线的上下两侧都有） |
| 端点 | 每张牌的「顶边中点」——holder 原点就是卡牌中心，顶边中点 = 原点沿局部 −y 半卡高（**带旋转**，因为手牌是扇形） |

### 9.2 素材

全部在 `CznHeidemarie/link_vfx/`：

### 9.5 拱高规则（方案 B）

```
spanRatio = 相邻两牌顶边中点距离 / 卡高

静止：arch = 卡高 × clamp(0.30 × spanRatio, 0.30, 1.20)
      ← 跨得越远拱越高，封顶 1.2 卡高（保证高过手牌）
拖拽：arch = 卡高 × lerp(0.30, 0.10, clamp((spanRatio - 1) / 3, 0, 1))
      ← 端点里有被拖的牌时反过来「绷直」

另有保护：拱顶（三次贝塞尔 t=0.5 处实际峰值 = 0.75 × arch）距视口顶至少留 24px
```

> **为什么不是"越远越平"**：链条只连「相邻的**连接牌**」，中间夹着普通牌时会被拉成
> 一条横跨整手牌的长带。早先统一按"拉远就压平"处理，长跨距就变成贴着牌顶的一条直线。

### 9.6 ⚠️ 纵深 / 让位（最容易踩的一条）

本视觉层是 `NPlayerHand` 的子节点、`z = 10`，和战斗 UI / 手牌处在**同一块画布、
同一个纵深区间**里。而整屏 UI 都是**普通 Control（不设 z）**，盖不住它 ⇒ **穿模**。

| 整屏 UI | 判据 |
|---|---|
| 抽牌堆 / 弃牌堆 / 消耗堆（`NCardPileScreen : ICapstoneScreen`） | `NCapstoneContainer.Instance.InUse` |
| 地图（`NMapScreen`） | `NMapScreen.Instance.IsOpen` |
| 卡牌奖励 / 选牌 / 其它浮层（`IOverlayScreen`） | `NOverlayStack.Instance.ScreenCount > 0` |

任一为真 → 整个收掉；关掉后**下一帧自动重建**（走 0.12s 权重淡入，观感不跳）。

另外链条按 `holder.IsVisibleInTree()` 过滤（与游戏 `ActiveHolders` 同口径）：
选牌模式 / 手牌收起时，卡还在容器里但不可见，不再给它们画光带。

### 9.7 状态动作

| 动作 | 表现 | 机制 |
|---|---|---|
| **拖起** | 光带被拉长（延展） | 键不变、端点跟手移动；补丁记下槽位索引，每帧把它插回链条原位 |
| **放下（取消）** | 光带自己缩回去 | holder 被放回容器，键仍不变 |
| **打出** | 连它的两条带淡出、端点收进邻牌；同时左右邻牌之间新出现一条带淡入（"重新接上"） | 权重 0.18s 淡出 + 新键 0.12s 淡入 |
| **切换卡拖动** | 过渡无缝 | 新旧 holder 的键都不变 |

> 光带以「holder 对」为键**常驻复用**（不是每帧重建节点），这是上面四种状态都不闪的原因。

卡面文件名里的 `<slug>` 是 C# 类名经 `StringHelper.Slugify` 派生的
（`HeidemarieFaintLight` → `heidemarie_faint_light`），由
`HeidemarieCard.PortraitPath` 拼出；文件缺失时自动回退 `FallbackPortraitPath`（战士占位图）。

### 10.2 为什么「图明明在，卡面却不显示」

**一张图要能被 `ResourceLoader` 找到，必须同时满足两件事：**

1. 源 PNG 有对应的 `.import`，且里面的 `[remap]` **有 `path=` 与 `dest_files=`**；
2. pck 里同时存在 `.import` 与它指向的 `.godot/imported/*.ctex`。

`.import` 里一旦出现 `valid=false`（Godot 导入被中断 / 源文件在扫描后又被改过），
Godot 仍会把这个 `.import` 打进 pck，但 `ResourceLoader.Exists()` 返回 `false` ——
于是 `AtlasResourceLoader` 判定卡面缺失，静默回落到占位图，**日志只有两条 ERROR**：

```
ERROR: Failed loading resource: res://images/packed/card_portraits/heidemarie/heidemarie_XXX.png.
WARN  AtlasResourceLoader: Missing sprite 'heidemarie/heidemarie_XXX' in card_atlas (...)
```

2026-10-18 的「微光 / 北极圈卡面不显示」就是这两个文件的 `.import` 被写成了 `valid=false`。

**修复方式**（任选其一，`build.ps1` 已加前置拦截，不会再静默漏出去）：
删掉坏 `.import` 后跑 `Godot --import`，或手工把 `[remap]` 的 `path` / `dest_files`
补成 `.godot/imported/<png>-<hash>.ctex`（hash 取 `.godot/imported` 里现有的同名文件）。
